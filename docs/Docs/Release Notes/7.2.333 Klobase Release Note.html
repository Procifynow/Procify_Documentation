4. Module: BOL​

Below are the list of new features/bug fixes developed as a part of the release in this module.

FeatureAdoptionTool & Short Description
PROC-27362 OData BO Support – Deep Update (Header + Child updates in a single call)NoBOL Extended OData support to allow deep update operations where both header and child entity data can be updated in a single API call. Previously, multi-level updates required sequential requests, increasing round trips. Clients can send nested JSON payloads containing parent entity properties along with child entity arrays. Child entities are automatically matched by parent key - existing children are updated, and new children are created.All operations are committed in a single transaction with full validation support. This significantly reduces overhead for complex entity hierarchies. Document Link Status: Tested
PROC-27343 BOL Node 512 MB Stability Verification & Issue ResolutionNoBOL Verified stability of the BOL Node running under a 512 MB memory constraint and resolved all identified issues. Ensures the platform operates reliably within constrained memory environments for applicable deployments. Status: Done - Closed
PROC-27366 Middleware: 1000 messages with no_sequence=0 took 17 minutes to processNoBOL - Middleware Resolved a middleware throughput issue where 1000 messages with no_sequence=0 took 17 minutes to complete against only 1 minute of actual processing time (16 minutes idle). Queuing and dispatch logic has been optimized to eliminate idle wait between message batches. Status: Tested
PROC-26465 Middleware: Default retry delay for deadlock/lock wait should be increasedNoBOL - Middleware For the middleware retry settings for Inbound Messages, the RetryDelaySeconds default value has been changed to 1 second in the config.json file. If it’s already overridden, then that value is not changed. Document Link Status: Tested
PROC-25080 Transport log showing source and target landscape as "undefined"NoBOL - Transport Fixed a transport logging defect where source and target landscape names appeared as "undefined" in the transport log. Landscape identifiers are now correctly resolved and displayed in all transport log entries. Status: Tested
PROC-26541 Indexing required on Users Permissions table – madm_user_permissionsNoBOL Added a composite index on the r_user_id & r_landscape column in the madm_user_permissions table to improve query performance for user-based permission lookups. Status: Tested
PROC-26503 Remove deprecated entity reference button or handle logic in BOL / BOL EditorNoBOL / BOL Editor Removed the deprecated entity reference-based condition button from the BOL Editor UI. Updated the underlying logic to prevent duplicate condition generation and to ignore deprecated backward-compatibility paths, eliminating developer confusion caused by legacy UI artifacts. Status: Tested
PROC-26994 Custom template should be enabled for OTP ServicesNoBOL OTP notification services can now use custom message templates. Previously OTP messages were fixed to a system template. Developers can now configure custom templates for OTP emails and SMS channels, enabling branded OTP communications per application. Status: Tested Reference Document : Notification Developer Guide
PROC-26106 Attachment: setAttachmentP() not working on server sideNoBOL Fixed a bug where setAttachmentP() called from server-side logic (entity callbacks or controllers) threw a "File Write Failed" error. The server-side attachment API now correctly processes and persists file data. Status: Tested
PROC-25752 Phase 02 Runtime – PIVOT/REPORT/CHART: Server-side pivotingNoBOL Implemented Phase 2 of server-side data pivoting. Pivot, Report, and Chart data transformations are now computed on the server instead of the client browser, reducing client-side load and significantly improving performance for large datasets. Status: Tested User Guide link: https://docs.google.com/document/d/1oNQqNsgTLLFqtPn7914ggasXzJTDXc-oSo6QBYq9T6Y/edit?tab=t.0
PROC-22355 API Versioning Behavior Creates Misleading User ExperienceNoBOL Corrected API URL versioning behaviour that was ignoring explicitly requested patch versions and automatically redirecting to the latest patch. API version resolution now honours the requested version, giving developers predictable and accurate versioning. Status: Done - Closed
PROC-25409 BOL Editor: Excel-uploaded entry not present after refreshing (Rollup status and Status Config)NoBOL Editor Fixed a persistence bug in BOL Editor where entries added via Excel upload were not retained after a page refresh in the Rollup Status and Status Config views. Uploaded entries now correctly persist to the database and reload on refresh. Status: Tested
PROC-24593 BOL Node 512 MB – OData GET ServicesNoBOL Validated and ensured OData GET service functionality is fully operational in the BOL Node 512 MB memory configuration. Addressed compatibility issues specific to this constrained memory deployment scenario. Status: Tested
PROC-25001 BOL/Metadata: adding vh to query parameter not updating query generationNoBOL Fixed a metadata query generation bug where adding a value help (vh) to a query parameter did not correctly update the generated query. The query generator now correctly incorporates vh-based parameters, ensuring accurate data retrieval. Status: Tested
PROC-24749 Training: get$Role() returning empty object {} in controller and consoleNoBOL Resolved an issue where get$Role() returned {} instead of the user's role data when called from a controller. The function now correctly retrieves and returns the active user role, consistent with $SYSTEM.roleId behaviour. Status: Tested
PROC-27146 Safeguards to prevent recursive invocation between entity callback and CommitP APINoBOL Added runtime safeguards to detect and break recursive call loops that occur when an entity callback triggers a CommitP API call, which in turn re-invokes the entity callback. Prevents infinite recursion and stack overflow in server-side business logic. Validation added in case the same transaction is being used for commitP() from callbacks throwing error as “Transaction commit is already in progress. Please wait for the current commit to finish before calling commit again.“. e.g., Developers should not use commitP() by using the same transaction at the rules callbacks - get the transaction from oEvent (function parameter) and use that for commitP() later on in the rules callback. Document Link 1, Document Link 2 Status: Tested
PROC-26611 SEAM4: error_code missing in kloerror when commitP failsNoBOL Fixed a bug where the error_code field was absent in the kloerror response object when a commitP operation failed. The error_code is now correctly populated, enabling downstream error handling to distinguish and respond to specific failure types. Status: Tested

5. Module: KloTouch​

Below are the list of new features/bug fixes developed as a part of the release in this module.

FeatureAdoptionTool & Short Description
PROC-27409 Option to select wizard screen type, plus known issues fixesNoKloTouch Added a UI Editor option to select the wizard screen type when creating screens. Previously this selection was only available via Developer AI. Also includes fixes for known issues in the wizard screen creation flow. Developers can now create wizard-type screens entirely from the UI Editor. Status: Tested
PROC-26662 REL_26/15-18 HomePage Editor: KL0018 testcase failing, Navigation not workingNoKloTouch Fixed a navigation regression in the HomePage Editor where the KL0018 test case was failing due to broken navigation on the homepage screen. Navigation flows on homepage-type screens now behave correctly per the defined test specification. Status: Tested
PROC-25246 Need busyIndicator while vh is loading data for F4NoKloTouch Added a busy indicator that displays while value help (vh) data is being fetched for F4 field searches. Previously the F4 popup gave no visual feedback during data load, creating confusion about system responsiveness. Status: Tested

10. Module: Business AI and Developer AI​

Below are the list of new features/improvements developed as a part of the release in this module.

FeatureAdoptionTool & Short Description
PROC-27164 Business AI – Application Context implementation Phase 2NoBusiness AI Completed Phase 2 of the Application Context feature for Business AI. This phase integrates kloQuery callbacks and additional AI context scenarios, enabling Business AI to generate queries and responses with richer, application-aware data. Status: Tested Reference Guide - Business_AI_User_Guide
PROC-26607 Developer AI – User/App level token limits and usage metricsNoDeveloper AI Implemented configurable token limit enforcement and usage tracking at user and application level for Developer AI. Administrators can now set per-user and per-app token quotas; usage metrics are tracked for governance and cost control. Status: Tested
PROC-27240 Developer AI – All LLM calls properly logged in LangSmithNoDeveloper AI All LLM calls from Developer AI are now captured in LangSmith with proper, searchable names. Previously generic entries made it impossible to isolate individual AI call chains. Each call now appears with a meaningful identifier. Status: Tested
PROC-27215 Developer AI – Early return on dependency failure in agentsNoDeveloper AI Added early-exit logic across RuleAgent, SchedulerAgent, NotificationAgent, and SampleDataAgent. If any upstream dependency fails mid-execution, the agent immediately returns a clear error instead of continuing with partial or misleading output. Status: Tested
PROC-26921 Developer AI – Code files fetched from actual repositoryNoDeveloper AI Developer AI now fetches existing code files directly from the version-controlled source repository instead of the local file system, ensuring AI modifications are based on the live codebase rather than potentially stale copies. Status: Tested
PROC-27598 Developer AI – Qdrant not supporting 3072 dimensionsNoDeveloper AI Fixed a vector storage compatibility issue where Qdrant rejected 3072-dimension embeddings. The Qdrant collection is now correctly configured to support the required dimensionality for the AI embedding model in use. Status: Tested
PROC-27565 Developer AI – Incorrect accountId in payload causing metadata save errorNoDeveloper AI Corrected a payload bug where an incorrect accountId caused AI metadata save operations to fail. The payload now correctly resolves and includes the authenticated user's accountId before submission. Status: Tested
PROC-27214 Developer AI – Run-only-jobs includes screen creation in responseNoDeveloper AI Fixed a response scoping issue where selecting "run only jobs" in Developer AI still returned screen creation results. The agent now correctly restricts execution and response to the selected job types only. Status: Tested
PROC-27128 Developer AI – Errors in Google Cloud logs during normal operationNoDeveloper AI Resolved error-level log entries in Google Cloud logs triggered by normal Developer AI operations. Log levels have been corrected and error handling improved to eliminate false-alarm log noise. Status: Tested
PROC-27034 Developer AI – Handle transient fields in SampleDataAgent/RuleAgents/NotificationAgentNoDeveloper AI Updated agents to correctly differentiate Regular, Transient, and Calculated property types. Previously transient fields were incorrectly included in insert operations, causing errors and invalid data generation. Status: Tested
PROC-27024 Developer AI – getEntitiesDetails API returning all properties as RegularNoDeveloper AI Fixed a logic bug where getEntitiesDetails returned all properties as "Regular" regardless of actual type. Property types are now correctly derived from entity configuration (Transient, Calculated, Regular). Status: Tested
PROC-27021 Developer AI – Attachment and GeoLocation must be transient, not regularNoDeveloper AI Corrected property type classification for Attachment and GeoLocation to Transient, as these are not persisted directly in the entity table. Ensures correct handling by all AI agents. Status: Tested
PROC-26309 Developer AI – Clear message when requested App is not foundNoDeveloper AI Improved error handling so Developer AI returns a clear, actionable message when a requested application does not exist, instead of a generic failure. Status: Tested
PROC-26281 Developer AI – Handle concurrent multi-user requestsNoDeveloper AI Implemented concurrency handling for simultaneous multi-user Developer AI requests. Each user's workflow now executes in full isolation, preventing session cross-contamination. Status: Tested
PROC-26278 Developer AI – Use incremental IDs for screens, remove datekeyNoDeveloper AI Replaced timestamp-based datekeys in AI-generated screen IDs with deterministic incremental IDs. Added duplicate ID checks. Produces cleaner, predictable identifiers for AI-generated screens. Status: Tested
PROC-26277 Developer AI – Multiple subscreen layouts incorrectly added to one subscreenNoDeveloper AI Fixed a screen generation defect where multiple subscreen layout definitions were attached to the same subscreen. Each subscreen now receives only its designated layout. Status: Tested
PROC-26271 Developer AI – Validate each metadata item created for screenNoDeveloper AI Added per-metadata validation during AI screen generation. Each generated metadata item is individually validated before persistence, allowing errors to be caught granularly. Status: Tested
PROC-25033 React Phase 01 – Playwright automationNoReact UI Implemented Playwright-based automated test coverage for React Phase 01 deliverables. Establishes a regression test baseline for the React UI track. Status: Tested
