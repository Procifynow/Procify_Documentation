2. Module: Dev Tools​

Below are the list of new features/bug fixes developed as a part of the release in this module.

FeatureAdoptionTool & Short Description
PROC-18103
Bol Editor :- entity index created with “client only” is being saved in db
Tools - Bol Editor		NoIf persistence is not maintained for an entity, it will be created on both the server side and the client side when the flavor network mode is set to offline.
Details: Bol editor
PROC-17872
Unable to create transnode using saved query
Tools - Dev Tools(Except BOL and UI Editor)		NoPreviously, saved search parameters were being reset when the Advanced Search Reset button was clicked. This has been improved so that saved query parameter values are retained on reset.
Specifically, if a saved query is added to the search transnode, its parameter values will no longer be cleared when performing an advanced search reset.
PROC-18227
Need version in adm and transport
Tools -ADM		NoADM and Transport have been versioned to reduce server restarts and to provide better visibility into the changes made within specific files or codebases of ADM and Transport.
PROC-17626
keep the job disabled while creating a new job in the job_instance screen.
Tools - Job Scheduler		NoAny new job created from the Job Instance screen will be in a disabled state by default. To run the job, you must manually enable it by clicking the Enable button.
During job transport, using the [Import Job] option, this will retain the job's original status. If the job was disabled before export, it will be imported as disabled; if it was enabled, it will be imported as enabled.
Details: Job Scheduler

VHQ for an entity created under some other entity
Bol		NoPreviously, when creating a VH query, it was possible to select either the current entity's name or queries created within that same entity. However, for saved queries, all saved queries from every entity were available.
This behavior has now been updated — you can now only select saved queries that were created within the current entity.

[PROC-17797](https://procifynow.atlassian.net/browse/PROC-17797)
Enable Query Usage Selection for Handling in getQueryP and getExecutedQuery APIs
BOL		NoWe have two database instances: Writer (RunTimeMain) and Reader (RunTimeSecondary).
By default, all queries are executed against RunTimeMain. However, you can shift the load of a specific query to the Reader instance by configuring the DB Selection property.
Note: Even when using RunTimeSecondary, any data updates to the properties of an entity set will still be persisted through RunTimeMain.
Details: Bol Editor
[PROC-15695](https://procifynow.atlassian.net/browse/PROC-15695)
Request Dump folder size is reached to 15 GB. Need analysis and optimization
BOL -BOL Server		NoThe `req_dump` folder will no longer store incoming request logs by default. To enable logging in this folder, you need to add the following flag to the `klarion.json` file:
`"enableReqDump": true`.
Additionally, full data payloads for all APIs will no longer be logged to Google Logs—only the necessary data will be captured.

6. Module: KloTouch​

Below are the list of new features/bug fixes developed as a part of the release in this module.

FeatureAdoption docShort Description
PROC-18324
KloTouch		YesIn previous versions, the autoHeight property of the CardList was not functioning as expected. Starting from this version, the issue has been resolved, and the autoHeight property will now behave correctly in CardList sub-screens.
If this property was configured and saved in earlier versions, you may start seeing its effect from this release onward. It is recommended to verify whether the autoHeight property was added intentionally or by mistake, and make any necessary adjustments manually using the UI Editor.
Details: Usage Record for autoHeight Property in KloCardlistConfig
PROC-17580
Corrections: pageLayout type "Two Column”
KloTouch		No"Flexible Column Layout (Deprecated – Use Two Column Instead)
This layout is similar to the Flexible Column Layout but supports the master-detail paradigm for only up to two pages. Unlike the Flexible Column Layout, it features a horizontal splitter between the two pages."
Refer: UI Editor- User Guide 7.0
