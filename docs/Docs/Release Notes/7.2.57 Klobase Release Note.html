1. Overview​

1.1 What are the changes?​

This Release contains new features/changes for the below areas of the framework.

AreaHas Changed?Adoption Required?
Dev Tools (UI Editor, BOL editor, menu, Online Code editor, App Cache-Control)YesNo
Dev Config ToolsNoNo
UI ControlsYESNo
BOLYesNo
KloTouchYesYes
ADMYesNo
Account ConsoleYesNo
System AdminNoNo
Index.htmlYESNo

For Application Team:

  • Changes have been made to the index.html file to include a new div for the upgrade banner. The application team will need to adopt this change by placing the div in their index.html to ensure the banner is displayed during the upgrade process. If the div is missing, the banner will not appear.Refer more here.

2. Module: Dev Tools​

Below are the list of new features/bug fixes developed as a part of the release in this tool.

FeatureAdoptionShort Description
PROC-13441
App utility screen enhancements (P2)		NoThe tool for building and validating different flavors, now called Validate and Publish (formerly known as App Utility), has been updated with new features.
1. A "Check logs" button has been added to the validate and publish screen. When clicked, it redirects to the Publish Logs screen, showing the status of the triggered build for the chosen flavors.
2. The screen will become non-editable during the build or validation process.
3. Flavors accessible only to managers will also be displayed in the apps dropdown.
PROC-12431
On Pivot - Disable download excel button when pivot/chart is selected in viewSelection		NoIf a user selects a Report or Chart in the Pivot Modeller or from the view selection, the download Excel button will be disabled.

3. Dev Config Tools​

No features are developed as a part of the release in this module.

4. Module: UI Controls​

Below are the list of new features/bug fixes developed as a part of the release in this tool.

FeatureAdoption docShort Description
PROC-11763
If uploading a attachment with same name it is not generating new ID.		NoControl KloAttach has been changed and a new property“sameFilenameAllowed” has been introduced to control the behavior when uploading attachments with identical filenames. This property determines whether multiple attachments with the same name can be uploaded.

5. Module: BOL​

Below are the list of new features/bug fixes developed as a part of the release in this tool.

FeatureAdoption docShort Description
PROC-13327
Azure login authentication failed- No error in rollbar		NoIf the Azure login or registration process encounters issues, such as token problems or sign-in errors, a Rollbar message will be sent to the server. The developer can then view the error log on the Rollbar dashboard.
PROC-13099
Chunk Generation API adoption during Registration and Upgrade		NoThis API is invoked during both registration and upgrades. It allocates chunks to the user, which are required for generating ID series numbers based on those chunks. This ensures that the user can continue adding data even while offline.
PROC-13079
At the end of build update require config should be broadcasted to other bol nodes		NoAt the end of the build update, the require config is broadcast to other BOL nodes, if the landscape is operating on multiple BOL nodes from which the build was accelerated.
PROC-11242
Config update failure case checking and showing in log		NoIf the app setup process fails for any app (including updating config), the errors can be viewed on the About page. Icons are used to indicate the setup status: green for success and red for failure.
Clicking on the icon opens a popup that displays any errors, if available. A "Download Log" button in the popup allows you to download the logs in a text file format. Additionally, the app can be reinstalled using the "Reinstall" button added in the popup.

6. Module: KloTouch​

Below are the list of new features/bug fixes developed as a part of the release in this tool.

FeatureAdoption docShort Description
PROC-14125
DOC: Need document for corrective action required for Open Dialog issue		NoDialogs opened via the KloController.openDialog API should be closed using the KloController.closeDialog API, not the sap.m.Dialog's close method. The sap.m.Dialog's close method should only be used when the dialog was opened via the sap.m.Dialog.open() method.
Note: Correcting Usage of KloController.closeDialog APIs
PROC-13368
In planning board, the user should be able to select any field value. As of now it is kind of hyperlink only and user is not able to select and copy it		NoIn the planning board,the application developer can now choose whether to enable or disable the DragAndDrop functionality of the ganttTable. By default it is enabled.
Note: Drag and Drop User guide
PROC-13347
O2C: Issue with Cardlist Screen Type - Data Not Growing as Expected		YesWhen using a cardlist section inside a splitter page layout, the growingScrollToLoad property of the cardlist section was not functioning as expected. To resolve this issue, a scrolling delegate was added to the cardlist section at runtime.
An adoption document detailing this fix has also been provided.
Note:This adoption is not required for all applications. It is only necessary for applications that use the cardlist section with the growingScrollToLoad property.
