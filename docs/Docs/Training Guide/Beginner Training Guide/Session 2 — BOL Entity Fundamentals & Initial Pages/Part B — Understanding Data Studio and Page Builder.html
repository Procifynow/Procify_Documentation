Part B — Understanding Data Studio and Page Builder

Before building screens, every developer must be familiar with the two core design tools in Klobase: the Data Studio (Procify Data Studio) and the Page Builder (Procify Page Builder). This part gives you an orientation of both tools and their layouts, then walks through building the Customer Complaints screen step by step — showing the expected output at each stage.

B.1 — Data Studio (Procify Data Studio) — Tool Layout​

Navigate to Design Studio → Data Studio. The editor is divided into two major sections: the Tree on the left and the Detail on the right.

SectionWhat It Does
Tree (Left)Lists all entities, queries, and value helps in the selected app. Click any item to load it in the Detail panel. Use Expand All / Collapse All to navigate. Use the search bar to find entities quickly.
Detail (Right)Shows all configuration tabs for the selected object: Properties, Relations, Object Type, Status, Queries, Rules, Entity Index. Only visible when an item is selected from the tree.
Toolbar (Top)Context-sensitive: Save, Edit, Update Schema, Validate, Delete, Test, Metadata File. Actions change depending on what is selected in the tree.
App SelectorDropdown at the top-left to switch between your assigned apps. Always verify the correct app is selected before making any changes.
Normal / Expert ModeToggle in the toolbar. Normal Mode: Entity, Query, Value Help creation. Expert Mode: adds Status Config, Object Group Config, Entity Index. Expert Mode needed from Session 3 onwards.
Note: Currently there is no difference between expert mode and normal mode
📘 Data Studio Reference
Source: Procify Data Studio 7.0 User Guide — Sections 2.0 Editor Sections, 1.4 Modes
Tree: expand, collapse, filter — same panel used for all entity operations.
Detail panel tabs depend on context: entity selected shows Properties/Relations/Status; query shows query config.
Update Schema: converts entity metadata into actual DB table. Required after every property change.
Test button: opens the Data Browser for CRUD operations on the entity directly from the editor.

B.2 — Page Builder (Procify Page Builder) — Tool Layout​

Navigate to Design Studio → Page Builder. According to the Procify Page Builder 7.0 User Guide, the editor is divided into four major sections:

SectionWhat It Does
Tree (Left)Hierarchical view of the entire page structure: Page → Page Layout → Page Area → Section → Controls. All creation, renaming, and assignment is done via right-click context menu in this tree.
Preview (Centre)Live render of the screen. Refreshes on Save. Use the Auto Refresh toggle for real-time updates. Full Preview loads actual data from the database for testing.
Detail (Down)Configuration panel for the selected tree element. Shows different properties depending on whether you have selected a Page, Page Layout, Page Area, Section, or Control.
Page Data Model (Right — Tab)TransNode configuration. Defines what data is available to the page. Use the + button to add Model Paths. Each TransNode has: an ID, an Entity/Query binding, a Node Type (EntitySet / Entity / Query), and an optional Fold From parent.
📘 Page Builder Toolbar Reference (Procify Page Builder 7.0 User Guide — Section 1.0)
Edit icon — enables edit mode on the tree. You MUST click this before creating or renaming anything.
+ icon — create a new page (blank or from wizard).
Save icon — commits all pending changes. Required before preview refreshes.
Show Full Preview — loads real database records into the preview for testing.
Detail icon — toggles visibility of the detail properties panel.
Page Data Model icon — toggles visibility of the TransNode / data model panel.
Reset Perspective — restores all panels to their default size and position.
Preview In — switch preview between desktop, tablet, and mobile device views.

B.3 — The Page Hierarchy (Procify Page Builder 7.0 User Guide — Sections 3.0–7.0)​

Every screen in Klobase follows a strict 5-level hierarchy. This is the most important structural concept in UI development. Each level has a mandatory naming convention prefix:

📘 Five-Level Page Hierarchy
Level 1 — PAGE (prefix: p_)
The root container. Holds all layouts. Created first. One page can have multiple layouts (one per device type).
At runtime, the platform picks the layout based on device: screencontainerdesktop, screencontainermobile, screencontainertab, screencontainerdefault.
Level 2 — PAGE LAYOUT (prefix: pl_)
Sits directly under the Page. Defines HOW the page areas are arranged.
screenType options: stack, tab, two_column, object_page, grid_layout, hsplitter, vsplitter.
Example: pl_complaints_desk (two column layout for desktop).
Level 3 — PAGE AREA (prefix: pa_)
A logical sub-container inside the layout. Can itself have a screenType (tab, stack, splitter).
Sections are assigned to page areas to determine WHERE they render.
Example: pa_complaints (list area), pa_complaint_details (detail area).
Level 4 — SECTION (prefix: s_)
The rendering unit. screenType determines HOW it displays data.
Types: search, cardlist, card, form, grid, tree, timeline, map, calendar.
Must be assigned to a Page Area to appear in the UI.
Example: s_search (search), s_complaints (grid), s_detail_header (form).
Level 5 — CONTROLS
Individual fields, buttons, labels, icons bound to entity properties.
Added via: right-click section → New → Controls, OR drag from unused TransNode properties.
Section screenTypeRenders As
searchFilter bar with Close / Reset / Search buttons. Auto-generates the search toolbar.
cardlistList of records as card rows — one card per record. Good for mobile and compact lists.
gridTabular list with column headers and rows. Supports sort, filter, group-by per column.
formDetail form layout. Each control renders as a labelled input field.
cardSingle entity rendered as a CSS grid card. One record only.
tabUsed on Page Areas to group child sections as tabs. showTitle must be true for tab labels.
treeHierarchical tree display for nested data.

B.4 — Page Data Model (TransNodes) — Concept​

The Page Data Model defines the data available to a screen. Every section and control that displays data must be bound to a TransNode. A TransNode is a “data pipe” — it fetches entity records from the database and makes them available to sections and controls on the page.

Node TypeFetches
EntitySetA LIST of records. Use for search sections, grids, card lists. Suffix convention: _list. Example: d_complaints_list
EntityONE record (the currently selected record). Use for detail forms. Suffix convention: _detail. Example: d_complaints_detail
QueryRecords from a kloQuery with WHERE conditions, joins, sorting. Suffix convention: _query.
OtherNon-standard / custom use cases.
📘 Fold From — The Critical Link Between List and Detail
When you create d_complaints_detail (Entity type) and set its “Fold From” = d_complaints_list,
the platform automatically loads the selected record’s data into d_complaints_detail whenever
the user clicks a row in the list. This is the mechanism that connects list → detail.
Without Fold From: the detail section will always be empty.
With Fold From: clicking any complaint row in the list instantly populates the detail form.
TransNode naming convention (from Procify Page Builder 7.0 Guide):
EntitySet → _list suffix Entity → _detail suffix Query → _query suffix

B.6 — Step 1: Create the Page (p_complaints)​

1Open Page Builder from Design Studio → Page Builder. Select your application from the app dropdown.
2Click the Edit icon in the toolbar to enable edit mode.
3Click the + icon → Create Blank Page.
4Page ID: p_complaints | Title: Employee Complaints | Lead Entity: d_complaints(use vh). Click Create.
5The page appears in the tree. No layouts yet — proceed to Step 2.

B.7 — Step 2: Create the Page Layout (pl_complaints_desk)​

The Page Layout sits directly under the Page and defines the arrangement type for all page areas. According to Procify Page Builder 7.0 Guide (Section 4.0): at runtime only one pageLayout is picked based on the device type — determined by the page’s screencontainerdefault, screencontainerdesktop, etc. properties.

1In the tree, right-click on p_complaints → New → Page Layout. A new layout is added to the tree.
2Right-click the new layout → Rename → enter: pl_complaints_desk. Press Enter.
3Click pl_complaints_desk in the tree to open its Detail panel on the right.
4In the Detail panel, set screenType = two column. This renders all assigned page areas one after another — the standard layout for list+detail screens.
5Now click on p_complaints in the tree. In its Detail panel, set screencontainerdefault = pl_complaints_desk. This tells the platform: use this layout on all devices unless a device-specific layout is set.
6Save.

📘 Layout Type Quick Reference (Procify Page Builder 7.0 Guide — Section 12.0)
stack — Sections / areas render one after another vertically. One subscreen shown at a time.
two_column — Master-detail split: left panel (list) + right panel (detail). Max 2 columns.
tab — Renders children as tabbed panels. Used at Page Area level for detail tabs.
object_page — SAP-style object page: sticky header + tab body sections.
hsplitter — Horizontal split with resizable rows.
vsplitter — Vertical split with resizable columns.
grid_layout / css_grid — CSS Grid-based placement. Requires modeller configuration.

B.8 — Step 3: Configure the Page Data Model (TransNodes)​

Select p_complaints in the tree. Click the Page Data Model icon (right panel tab). Click + to add Model Paths. Create the two root TransNodes:

1Click + in the Page Data Model panel. Dialog opens.
2Node Path : search | Entity/Query: d_complaints | Node Type: Query. Click OK.
3Click Transfer&Link of search. Node Path: list
4Click Transfer&Link of list Node Path: detail
5Save. These two TransNodes are the data backbone for all sections on this page.

B.9 — Step 4: Create the List Page Area (pa_complaints)​

Per Procify Page Builder 7.0 Guide (Section 5.0): The Page Area is the next level after Page Layout. Page Areas are embedded with the Page Layout via the Layout Data assignment.

1Right-click on pl_complaints_desk → New → Page Area. A new page area is added.
2Right-click the new page area → Rename → pa_complaints.
4Save.

B.9.1 — Creating the Search Section (s_search)​

Per Procify Page Builder 7.0 Guide (Section 6.1): To add a new section, right-click on the page area and select New → Section. The search screenType auto-generates the filter bar with Close / Reset / Search buttons.

1Right-click on pa_complaints → New → Section. Rename it: s_search.
2In the Detail panel, set screenType = search.
4Select s_search in the tree. In the Detail panel, set the TransNode (path) = search.
5Add controls: right-click s_search →click New in poup → Controls . OR go to the Page Data Model panel → select search→ Unused Properties tab → drag properties directly to s_search in the tree.
6Add all controls as listed in the note below. Save after each set.

3. The control is created automatically with the property binding pre-set.

B.9.2 — Creating the Complaints List Section (s_complaints)​

The grid section renders complaint records as rows with sortable, filterable columns. Per Procify Page Builder 7.0 Guide (Section 6.2 — Grid): For desktop view, section screenType should be “grid”. Add a conf_grid000 config node for grid behaviour settings.

1Right-click pa_complaints → New → Section. Rename: s_complaints.
2In the Detail panel, set screenType = grid.
3Set TransNode path = list.
4Right-click pa_complaints → New → Assign → select s_complaints (below s_search). Save.
5Add controls from d_complaints_list TransNode unused properties: ticket_id (set the control type as m.link and add press event with function as ‘navTo’(Fill the sunscreen id as detail page area) ), customer_id, priority, s_status, planned_res_dat, closed_on, sales_manager.
6Right-click s_complaints → New → Config → rename: conf_grid000. This config node stores grid behaviour properties.
7Right-click s_complaints → New → Toolbar. Add Add and Delete buttons in the toolbar detail.
8Arrange the controls in s_complaints by using drag and drop feature inside section
9Save.

B.10.3 — Creating the Detail Area (pa_comp_details)​

pa_comp_details is a nested Page Area inside pa_complaint_details.

1Right-click page area→ New → Page Area. Rename: pa_comp_details.
2In the Detail panel, set screenType = default. Set showTitle = true & title = detail so tab labels are visible.
3Assign the page area to pa_complaints_detail.
4Now create all 4 sections inside pa_comp_details. Right-click pa_comp_details → New → Section for each. Set each to screenType = form Set TransNode = detail for form sections.
5Set each section’s title property — this becomes the tab label visible at runtime.
5Assign all 4 sections to pa_comp_details in the correct sequence. Save.
6Set type = header for s_detail_header layout & type = section for pa_comp_details.
7Set press event for complaint_id link with function as navTo => pageArea : pa_complaint_details.

B.10.3 — Add Action buttons for pa_comp_details​

1Right-click pa_comp_details→ New → Toolbar.
2Set showAdd and ShowDelete = false
3Right-click section-Toolbar → New → Action/Button.
4Right-click button01 → rename → edit
5Set text = Edit | icon = sap-icon://edit | add press event and fill this.setMode('EDIT')

B.11 — Step 6: Preview and Verify the Complete Screen​

1Save all changes in the Page Builder.
2Click Show Full Preview. The screen loads with live complaint data from the database.
3Verify the search bar appears at the top: Ticket Id, Status, Complaint Type, Escalated, Employee Category, Priority fields visible. Close / Reset / Search buttons present.
4Verify the complaint list appears below the search bar with columns: ticket_id (clickable link), customer_id, priority, status, planned resolution date, closed date.
5Click a complaint row. Verify the detail area loads with the header section (description, status, priority) and the tab area below.
6Navigate through each tab — Complaint Details, Assignment, Reporter Info, TAT & Timeline, Complaint Items. Verify correct fields in each.
7If a section appears blank: select it in the tree and check that its TransNode path is correctly set in the Detail panel. Ensure Fold From is set on d_complaints_detail.
