Part E — Coding Standards

These standards are non-negotiable on all Procify projects. Violations result in code review rejection and technical debt. The principles come from kloTouch 7.0 Basic Training Guide §7.4 and §7.5.

E.1 — Controller File Standards​

RuleDoDon'tReason
ScopeWrite ONLY UI logic in the controller: formatters, navigation, show/hide, model reads for display.Write business logic (status transitions, validations, default-setting) in the controller.Business logic in the controller bypasses server validation and breaks when the screen is accessed via API.
TypeScript typingDeclare every variable with its type: const count: number = 0; const msg: string = '';Use implicit any: let x = someValue; or omit types on function parameters.Untyped code hides bugs at compile time that surface as runtime errors in production.
Variable declarationDeclare variables only when necessary. Prefer const over let.Declare variables at file scope (class properties) when a local variable suffices.File-scope variables persist across page navigations and cause state leakage between sessions.
Nested functionsKeep functions flat. Extract complex logic to named private methods.Nest arrow functions inside controller methods: onClick(() => { const x = () => {...}; })Nested functions are not testable, not readable, and difficult to debug.
Async/awaitUse async/await for all TransNode API calls. Mark the function async.Use .then().catch() promise chains.Consistent await pattern is required by the framework for proper error propagation.
Deprecated APIsAlways use navTo(), tm.commitP(), this.setMode().Use navToS(), navToByEvent(), getTN('x').commitP()Deprecated APIs are removed in future versions. Using them creates upgrade risk.
Model mutationOnly modify model properties via setProperty() for transient display values.Directly mutate entity properties from the controller (entity.some_prop = value).Direct mutations bypass the dirty-tracking mechanism and do not persist on save.

E.2 — Entity File Standards​

RuleDoDon't
ScopeWrite ONLY business logic in entity files: onCreate defaults, onUpdate role checks, onDelete restrictions, beforeQ filtering, OnValidate.Write navigation or UI state changes in entity files.
Setter functionsUse setter override pattern to automatically derive related values when a property changes.Compute derived values in the controller on button press — this is bypassed when data changes via API.
Validation locationAll mandatory field checks and business rule violations go in OnValidate.Throw errors in onAfterCreate — onAfterCreate is called AFTER the record is saved; errors there cause data inconsistency.
Error handlingAlways wrap async BOL API calls (createEntityP, LoadEntityByKeyP) in try/catch and log errors.Let unhandled promise rejections propagate silently.
Role checks in rulesUse oEvent.getTxn().$SYSTEM.roleID to get the runtime role and enforce role-specific logic.Hardcode user IDs or email addresses for role checks.

E.3 — Naming Conventions​

ItemConventionExample
Pagesp_ prefix + snake_case descriptionp_complaints, p_complaint_dashboard
Page Areaspa_ prefixpa_complaint_details, pa_complaints
Sectionss_ prefixs_complaints, s_detail_header
Entitiesd_ prefixd_complaints, d_complaint_item
Queriesq_ prefixq_complaints, q_customers
Transient propertiest_ prefixt_open_count, t_selected_count
Controller functions (formatters)format + PascalCaseformatPriority, formatTAT, formatStatusLabel
Controller functions (event handlers)on + PascalCase + actiononEditPress, onSavePress, onDeleteConfirm
Variables in TypeScriptcamelCase + explicit typeconst openCount: number = 0;
Boolean variablesis/has prefixisEscalated, hasAttachment, isLoading

⚠ Private Node must be running whenever you test controller functions, formatter functions, or OnValidate. Without the Private Node, server-side hooks are bypassed and the client shows incorrect results. Always verify Private Node status in the App Builder toolbar before testing.
