Part F — Preparing the Landing Page

F.1 — What Is a Landing Page?​

The landing page is the first screen a user sees after logging into the application. In the Customer Complaints Application, p_complaints_dash will serve as the landing page — the list of complaints filtered by role will be immediately visible after login.

There are two things needed to make p_complaints_dash the effective landing page:

  • Create a dashboard screen.

  • Configure it as landing page

The screen we are going to create will be as mentioned below.

F.1 — create dashboard screen?​

Dashboard also follows p_complaints page with limited changes

#ActionDetail / Code
1Create dashboard pageNavigate to the page builder screen and select customer_complaints application. And create a blank page. Fill id : p_complaint_dashboar | title : p_complaint_dashboar
2Create page layoutCreate page layout pl_desktop and mark screen type as default
3Create page_areaCreate page area pa_dashborad and mark screen type as default
4Create sectionCreate section s_dashboard and mark screen type as card
5Add titleAdd m.Text control and fill text : Status Wise Count
6Add control1 Add m.VBox control with properties alignitems : center
2. Add items aggregation
3. Expand and right click on items:<control-id> new → control → m.Text → text: New
4. Expand and right click on items:<control-id> new → control → m.Text → text: 0
7Repeat stepsRepeat step 6 for closed,onhold,escalated,inprocess,backlog,reopen
8Create page data modelCreate search and list transnodes using q_complaints.ts

Model the card with modeler as mentioned below

After this you might have noticed the screen contains 0 rather than actual count for this controller is required which will be covered later and at that time we will update the dashboard as well.
