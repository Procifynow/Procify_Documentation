Session 5 Assignment

⚠ Complete ALL mandatory tasks before Session 6
Session 6 (Bindings, Navigation & Styling) builds the visual layer on top of the logic implemented today.
All entity hooks must be working before styling is applied.

Mandatory Tasks​

Perform all the tasks performed in session 05

#ActionDetail / Code
1Verify onAfterCreateCreate a new complaint from the UI. In Data Browser, confirm: s_status = OPEN, assigned_to = your login ID. Private Node terminal shows the info log.
2Verify V001Try to save a complaint with complaint_desc = 'Short'. UI must show the V001 error on the complaint_desc field. Fix and save successfully with 10+ char descriptions.
3Verify V002Save a complaint without selecting priority. V002 error must appear. Select priority and save again — should succeed.
4Verify V003/V004Set planned_resolution_date to yesterday. V003 must fire. Set to tomorrow — should pass. Set to a date before today's session — V004 must fire if it's before created_on.
5Verify V005Log in as emp_<prid>. Try to change s_status to CLOSED and save. V005 error must appear. Log in as mgr_<prid>, make the same change — it must succeed.
6Verify closed_on setterLog in as mgr_<prid>. Set s_status to CLOSED and set closed_on to today. After saving, check actual_tat in Data Browser — should be the computed number of days since complaint creation.
7Verify landing page default filterLog in as emp_<prid>. On page load, the list should automatically show only that user's complaints (sq_my_complaints applied). Log in as mgr_<prid> — list should show all OPEN complaints (sq_all_open applied).
8Verify beforeQ row-level filteringRepeat the role-based checks from E.4: Employee sees only their own complaints, IT Team sees only assigned ones, Manager sees everything.
9Verify afterQ computed fieldConfirm days_open renders correctly for at least one old and one newly-created complaint.

Exploration Task (Optional — Bonus)​

  • Add a V006 validation: if is_escalated = true and responsible_team is empty, block save with message: 'Escalated complaints must have a responsible team assigned.'

  • Implement onDelete hook: log a message 'Complaint deleted: {complaint_id} by {user}' and push an entry into d_complaint_voices as an audit trail before deletion.

Session 6 Preview — What Comes Next​

📘 Session 6: Bindings, Navigation & Styling
With business logic in place, Session 6 focuses on the presentation layer — making the application look and navigate well.
Bindings: Connecting controls to properties and formula expressions (binding a label text to computed values).
Navigation: Implementing the complaint_id navigation link — clicking a complaint ID in the list loads the detail screen for that specific complaint.
Styling: Applying predefined style classes (status badge colours — OPEN=blue, INPROCESS=orange, etc.) and custom CSS classes to sections and controls.
By end of Session 6, the application will look and feel production-ready at the complaint list and detail level.
