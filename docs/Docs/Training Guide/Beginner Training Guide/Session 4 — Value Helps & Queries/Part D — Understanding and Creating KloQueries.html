Part D — Understanding and Creating KloQueries

D.1 — What Is a KloQuery?​

A KloQuery is the Klobase equivalent of a SQL SELECT statement. It lets you define — within the Data Studio — exactly what records to fetch, from which entity, with which filters, joins, and sort order. Unlike a Runtime Entity Query (which simply fetches all records of an entity), a Modelled Query gives you full control over the WHERE clause, JOIN entities, and sort order — and is reusable across multiple pages.

Query TypeWhen to Use
Runtime Query (Entity Query)Fetch all records of a single entity. No WHERE clause in the definition. Filters applied at runtime via the TransNode. Use for simple list screens.
Modelled Query (Dynamic Query)Define custom WHERE conditions, joins, sort order in the Procify Data Studio. Reusable, entity-independent. Use for role-filtered lists (My Complaints), VH Queries backed by joins, aggregated results.
Native Query (Advanced Query)Raw SQL. Database-specific. Use only for special cases not achievable with modelled queries. Avoid training.
📘 KloQuery Fields Reference (Procify Data Studio 7.0 User Guide — Section 3.0.2)
Return Entity: The entity whose properties appear in the result set.
Query Type: Runtime | Modelled | Native — affects which tabs are available.
Entities And Join: Add the root entity and any joined entities (LEFT JOIN, INNER JOIN, etc.).
Select Properties: Choose which properties from the entities appear in the result.
Parameters: Define input parameters the query accepts at runtime (e.g., user_id filter passed from the TransNode).
Where: Define filter conditions: entity.property = :parameter or entity.property = 'fixed_value'.
Sort Order: Set the default sorting column and direction (ASC / DESC).
Naming convention: Query IDs must start with q_. All lowercase.

D.2 — Queries to Create in This Session​

Query IDTypePurpose
q_complaintsModelledEmployee: shows only complaints assigned to the logged-in user

D.3 — Step-by-Step: Creating q_my_complaints​

#ActionDetail
1Click + → QuerySelect d_complaints entity and click + → Query. Fill : q_complaints and click create then save.
2Open q_complaintsClick q_my_complaints in the tree. The Detail panel shows the query configuration tabs.
4Select Properties tabClick the Select Properties tab. By default, all d_complaints properties are included. Remove any you do not need to reduce payload. Keep it all for now.
5Add ParameterClick the Parameters tab. Click Add. Parameter ID: current_user | domain : String | Description: Login ID of the current user.
Note : perform the same for all the properties available in s_search section
6Add WHERE clauseClick the Where tab. Click Add. Fill: Entity Property: d_complaints.assigned_to | Operator: = | Right Value: :current_user (the parameter defined in Step 5). Click Save.
Note: perform the same for all the properties available in s_search
7Add Sort OrderClick the Sort Order tab. Click Add. Field: d_complaints.created_on | Order: DESC. This shows the newest complaints first.
8SaveClick Save. q_my_complaints is ready.
