Part D.1 — Team Groups: Bulk User Assignment

What Is a Team Group?​

Assigning one test user at a time (as done in Part D) works fine for training, but it does not scale. Real projects onboard users in batches — a new hire cohort, an entire department, or a partner organisation that all needs the same app access on day one. Team Groups (labelled User collections inside the Workspace Hub screen) solve exactly this: they let you bundle a set of users once and assign the whole bundle to an application in a single step, instead of repeating the Part D steps per user.

Team Groups are of two kinds:

  • Individual Team Group — created automatically for every user the moment their account is created. Hidden by default (use the Show Individual checkbox to reveal them). Its only job is to let a newly created app be auto-assigned back to the user who created it.

  • Group Team Group — created manually by an admin, and the one you will use for real onboarding work. It holds any number of users and can be linked to one or more App Collections (App Collections) so that every user in the group inherits access to every app in the collection

Why Team Groups Matter in Practice

  • Without Team Groups, assigning 25 new employees to 3 apps means 75 manual assignment actions (Part D, repeated).

  • With a Team Group, it becomes: 1 group with 25 members, linked once to an App Collection with 3 apps.

  • Team Groups are filtered by the logged-in user’s Auth Configuration and scoped to the current landscape — you will only see groups you are authorised to manage.

Scenario — Onboarding the Response Team​

The Customer Complaints BRD defines a ResponsibleTeam persona made up of several support agents, not just one test user. Rather than repeating Part D for each agent individually, model the onboarding the way a real project would:

ActionDetail / Code
Create the Team GroupNavigate to Workspace Hub → User Collections (Team Groups). Click Add. Name it grp_response_team_<prid>.
Add members
Open the group, click Add under members, and select 3–4 existing users (or the test users created earlier in this session) to represent the support agents.
Link to an App Collection
Under the group’s App Collections tab, add the Customer Complaints App Collection so every member inherits the ResponsibleTeam role assignment.
Verify in bulk
Log in as any one member. Confirm the app is visible, exactly as verified individually in Part D — but this time achieved through the group, not a per-user step.

Excel Upload for Team Groups​

For onboarding sets larger than a handful of users, Team Groups also support bulk Excel upload/download, so a spreadsheet of usernames can populate group membership without clicking through the UI one row at a time. This is the same mechanism used for App Collections and is the recommended approach once a group exceeds roughly 10–15 members.

🛠 Hands-On — Try It Yourself

  • Export your grp_response_team_<prid> group to Excel.

  • Add two more (fictional) usernames as new rows.

  • Re-upload the file and confirm the new rows appear as pending/invalid members (since

those users don’t yet exist) — this is expected and demonstrates the validation Procify performs on upload.
