Part F — Creating the d_complaints Entity and Initial Page Using the Wizard

Now that you understand what Procify eliminates, you will experience it firsthand. You will create the d_complaints entity and its Complaints list screen — using the Page Wizard — in this session. Session 2 will rebuild the same screen step-by-step so you understand every level of the hierarchy.

F.1 — Open the Data Studio​

1Log in to the platform as your developer account.
2From the main menu, expand Design Studio → select Data Studio.
3In the application dropdown at the top of the tree, select your app: customer_complaints_<prid>.
4The tree is currently empty. You will add d_complaints now.

F.2 — Create the d_complaints Entity​

⚠ Naming rules — read before creating anything
Only lowercase letters, numbers, and underscores. No spaces, hyphens, or capitals.
IDs cannot be changed after creation — a wrong name requires deleting and recreating.
Never use "user" as an entity ID — reserved keyword in MySQL.
d_ prefix = Runtime Entity — always use this prefix for transactional entities.
1Click the + button in the tree → select Entity. The entity creation dialog opens.
2Entity ID: d_complaints. Click Create.
3When prompted for the Primary Key — Property ID: complaint_id | Kind: Primary | Data Type: Auto Number. Click Submit.
4Click Save. d_complaints appear in the left tree.

F.3 — Add All Properties to d_complaints​

Follow the steps below to add each property. The complete property reference table is in Part A.

1Click on d_complaints in the tree to select it.
2Click on the Properties tab in the detail panel.
3Click the + button to add a new property. The qualifier selection menu opens.
4Select the qualifier (Regular for most properties) → fill in Property ID, Data Type, and Short Label.
5Toggle key attributes where required: ❗ Mandatory for complaint_desc.
6Click Save after each batch of properties.
7Repeat for all 20 properties listed in the d_complaints table in Part A.
⚠ Data type reminder
Use Text (not String) for complaint_desc and remark — they exceed 255 characters.
Use Timestamp for all date fields: first_response_date, planned_resolution_date, closed_on, created_on, modified_on.
Use Boolean for is_escalated — not String.
Use Decimal for actual_tat and standard_tat.

F.5 — Create Test Data​

1Click d_complaints in the tree → Toolbar → Data Browser → Execute → Add.
2Record 1: complaint_desc: "Product quality issue with batch B-101" | priority: High | assigned_to: emp_<prid> → Save.
3Record 2: complaint_desc: "Delayed delivery for order ORD-2025-001" | priority: Medium | assigned_to: emp_<prid> → Save.
4Record 3: complaint_desc: "Billing discrepancy on invoice INV-4521" | priority: Low | assigned_to: emp_<prid> → Save.

F.6 — Create the Complaints Page Using the Wizard​

The Page Wizard creates a full working screen — with page, layout, area, section, and controls — in a few clicks. Use it now to produce your first Complaints screen quickly. In Session 2 you will build the same screen manually, step-by-step, so you understand every level.

1From the main menu, open Page Builder (under Design Studio).
2In the application dropdown, select customer_complaints_<prid>.
3Click the Edit icon → click the + icon → select Create Page from Wizard.
4Page ID: p_complaints | Title: Complaints | Lead Entity: d_complaints. Click Next.
5Select the page template: List & Detail (this generates a search bar, a card list, and a detail form).
6In the entity property selection screen, tick all properties you want on the list card: complaint_id, complaint_desc, priority, assigned_to, created_on.
7In the detail form selection, tick all properties. Click Generate.
8The wizard creates the full page hierarchy automatically. Click Save.
9Click Show Full Preview to verify the three test complaint records appear as cards in the list.
📘 What the wizard created
Page: p_complaints (with route /complaints)
Page Layout: pl_complaints_desk (Stack type)
Page Area: pa_complaints (assigned to the layout)
Section: s_complaint_search (Search type — for filtering)
Section: s_complaint_list (CardList type — shows all complaints)
Section: s_complaint_detail (Form type — shows one selected complaint)
All controls bound to the correct d_complaints properties automatically.
In Session 2 you will understand every one of these elements and rebuild it from scratch.

Session 1 Assignment​

Complete all mandatory tasks before Session 2. The trainer will verify each item at the start of Session 2 before proceeding.

Mandatory Tasks​

1. Create the application customer_complaints_<prid> in the Workspace Hub.

2. Create three roles: it_employee (prec 3), employee_manager (prec 2), it_team (prec 1).

3. Create three test users: emp_<prid>, mgr_<prid>, it_<prid>.

4. Assign emp_<prid> → it_employee. Assign mgr_<prid> and your developer account → employee_manager. Assign it_<prid> → it_team.

5. Verify all three test users can log in (incognito windows) and see the application.

6. created a d_complaints entity with all 20 properties. Update Schema → success toast confirmed.

7. Create 3 test complaint records using the Data Browser.

8. Create page p_complaints using the Wizard. Verify 3 cards visible in preview.

  1. Create a Team Group (grp_response_team_<prid>) with at least two of your test users as members, link it to the app’s App Collection, and verify both members can see the application without being assigned individually.
