Part E — Validate & Publish

E.1 — Validate vs. Publish — What's the Difference?​

ActionWhat It DoesWhen to Use
ValidateScans the application for errors WITHOUT building. Safe — nothing changes in the running app.Run first, every time. Fix all errors before triggering Publish.
PublishValidates first, then builds the app if no blocking errors exist. Updates the running app.After Validate passes with 0 errors. Use Full Build for first publish or after VH Config changes.

E.2 — Common Publish Blockers​

BlockerCauseFix
VH Config not visible in UI after PublishVH Config changes require a Full Build.Always select 'Full Build' for the first publish or after adding/editing VH Configs.
TypeScript compilation errorSyntax error in entity .ts or controller .ts file.Open VS Code → check terminal for tsc errors → fix, save, re-validate.
Update Schema not runEntity properties added but schema not updated in DB.Data Studio → select entity → Update Schema → confirm success toast.
Another build IN-QUEUEA previous build is already running.Click 'Proceed' to queue behind the current build. Do NOT cancel it.
Missing app_util flavorBuild & Deploy menu not visible.Ask trainer — app_util must be assigned to your developer account.

E.3 — Step-by-Step: Build & Deploy​

1Open Build & Deploy
Hamburger menu (☰) → App Builder → Build & Deploy.
(If this menu item is missing, app_util flavor is not assigned to your account. Ask the trainer.)
2Enter the Application
In the App field, type customer_complaints_<prid> and press Enter.
The application version details load.
3Run Validate First
Select Action: Validate.
Click Submit.
Wait for the validation report to generate.
Download the XLSX report if errors are listed.
Fix every ERROR before proceeding. Warnings can be reviewed but do not block the build.
4Fix All Errors
For each error in the report:
- Missing Update Schema → Data Studio → Update Schema on the entity.
- TypeScript error → VS Code → fix tsc error → save → re-validate.
- Missing VH Build → select Full Build in the next step.
Re-run Validate until the report shows 0 errors.
5Run Publish
Select Action: Publish.
Build Type: Full Build (required for first publish and after any VH Config changes).
Click Submit.
The Publish Log shows the progression:
IN-QUEUE → IN-PROCESS → PUBLISHED
Do NOT navigate away while the build is running.
6Verify the Published App
Log out completely.
Log back in.
Open the hamburger menu → confirm 'Complaints' item is visible.
Navigate to p_complaints → confirm live data loads.
Verify: status badges render, VH dropdowns populate, all tabs in detail section work.
