# Part A — Setting Up the Private Node Environment

*Reference: [Private Node setup Guide](https://sites.google.com/procifynow.com/procifyhelpcenter/application-development/reference-manual)*

The Private Node is a local Node.js server running on your laptop that acts as the workspace server for your development session. Instead of your browser talking to the shared landscape server, it talks to your VS Code instance — giving you full debugging capability and instant iteration on server-side code.

### Pre-requisites

| **Requirement**                  | **How to verify**                                                                                     |
|----------------------------------|-------------------------------------------------------------------------------------------------------|
| VS Code installed                | Open VS Code — if it opens, you are good.                                                             |
| Procify VSIX extension installed | Extensions (Ctrl+Shift+X) → search 'Procifynow'. If not installed, ask the trainer for the VSIX file. |
| Network access to the landscape  | Open your landscape URL in a browser. If the login page loads, connectivity is confirmed.             |
| Node.js installed                | Open a terminal: node --version. You should see v22+.                                                 |

### Setting the Private Node in VS Code

| **1** | **Create Your Workspace Folder**<br/>Create a new folder on your laptop: Documents/PrivateNode/srm_&lt;your_prid&gt;. All application server-side files will be downloaded here. |
|---|---|

| **2** | **Open the Folder in VS Code**<br/>File &gt; Open Folder &gt; navigate to your new folder &gt; click Open. |
|---|---|

| **3** | **Open the Command Palette**<br/>Press Ctrl+Shift+P (Windows/Linux) or Cmd+Shift+P (Mac). |
|---|---|

| **4** | **Run Procify Version Selection**<br/>Type: Procifynow: Procify IDE Setup and press Enter. A WebView panel opens on the right. |
|---|---|

| **5** | **Enter Your Landscape URL**<br/>In the WebView, enter your app URL — e.g. https://dev.procify38.com/p6/srm_pr0045/index.html. Click Next. |
|---|---|

| **6** | **Enter Developer Credentials**<br/>Enter your developer username and password. Click Start Setup. |
|---|---|

| **7** | **Wait for Initialisation**<br/>The VS Code file explorer will populate with folders (entity stubs, controller stubs, kloconfig, etc.). A confirmation message appears when complete. |
|---|---|

| **8** | **Checkout application**<br/>The VS Code will open a webview to checkout the assigned apps. Select the created app and perform checkout |
|---|---|

## A.2 — Entity File Location and Structure

The entity .ts file for d_complaints is located in the Private Node workspace at the path:

| workspace/apps/\<your_app_id\>/d_complaints.ts |
|------------------------------------------------|

If the file does not exist yet, the private node can generate it. The base structure looks like this:

| import \{ KloEntity, ValidationError, ErrorType \} from 'klobase';<br/>export class d_complaints extends KloEntity \{<br/>// ── Getters &amp; Setters ──────────────────────────────────────────<br/>// ── Lifecycle Hooks ────────────────────────────────────────────<br/>public async onAfterCreate(): Promise&lt;any&gt; \{<br/>// Called after a new complaint record is created<br/>\}<br/>public async OnValidate(): Promise&lt;any&gt; \{<br/>// Called during navigation if transnode setActiveIf = Valid<br/>\}<br/>public async onDelete(): Promise&lt;any&gt; \{<br/>// Called after the record is deleted<br/>\}<br/>\} |
|---|

| **💡 Architecture Principle: Business Logic Belongs Here**                                                                                                       |
|------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| The entity file is the authoritative location for all business logic. Period.                                                                                    |
| Controller file → UI orchestration only (navigation, formatter functions, show/hide decisions).                                                                  |
| Entity file → field defaults, cross-field computations, validations, role enforcement.                                                                           |
| Never duplicate validation logic in the controller. If the controller calls commitP(), OnValidate() fires automatically on the server — that is your safety net. |
| Reference: kloTouch 7.0 Basic Training Guide — Section 7.5 Best Practice Do's and Don'ts (Entity File).                                                          |
|                                                                                                                                                                  |
