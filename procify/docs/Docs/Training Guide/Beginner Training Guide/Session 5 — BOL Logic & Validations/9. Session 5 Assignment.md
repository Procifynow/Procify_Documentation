# Session 5 Assignment

| **⚠ Complete ALL mandatory tasks before Session 6**                                                       |
|-----------------------------------------------------------------------------------------------------------|
| Session 6 (Bindings, Navigation & Styling) builds the visual layer on top of the logic implemented today. |
| All entity hooks must be working before styling is applied.                                               |
|                                                                                                           |

## Mandatory Tasks

Perform all the tasks performed in session 05

| **\#** | **Action**                             | **Detail / Code**                                                                                                                                                                                                       |
|--------|----------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **1**  | **Verify onAfterCreate**               | Create a new complaint from the UI. In Data Browser, confirm: s_status = OPEN, assigned_to = your login ID. Private Node terminal shows the info log.                                                                   |
| **2**  | **Verify V001**                        | Try to save a complaint with complaint_desc = 'Short'. UI must show the V001 error on the complaint_desc field. Fix and save successfully with 10+ char descriptions.                                                   |
| **3**  | **Verify V002**                        | Save a complaint without selecting priority. V002 error must appear. Select priority and save again — should succeed.                                                                                                   |
| **4**  | **Verify V003/V004**                   | Set planned_resolution_date to yesterday. V003 must fire. Set to tomorrow — should pass. Set to a date before today's session — V004 must fire if it's before created_on.                                               |
| **5**  | **Verify V005**                        | Log in as emp\_\<prid\>. Try to change s_status to CLOSED and save. V005 error must appear. Log in as mgr\_\<prid\>, make the same change — it must succeed.                                                            |
| **6**  | **Verify closed_on setter**            | Log in as mgr\_\<prid\>. Set s_status to CLOSED and set closed_on to today. After saving, check actual_tat in Data Browser — should be the computed number of days since complaint creation.                            |
| **7**  | **Verify landing page default filter** | Log in as emp\_\<prid\>. On page load, the list should automatically show only that user's complaints (sq_my_complaints applied). Log in as mgr\_\<prid\> — list should show all OPEN complaints (sq_all_open applied). |
| **8**  | **Verify beforeQ row-level filtering** | Repeat the role-based checks from E.4: Employee sees only their own complaints, IT Team sees only assigned ones, Manager sees everything.                                                                               |
| **9**  | **Verify afterQ computed field**       | Confirm days_open renders correctly for at least one old and one newly-created complaint.                                                                                                                               |

## Exploration Task (Optional — Bonus)

- Add a V006 validation: if is_escalated = true and responsible_team is empty, block save with message: 'Escalated complaints must have a responsible team assigned.'

- Implement onDelete hook: log a message 'Complaint deleted: \{complaint_id\} by \{user\}' and push an entry into d_complaint_voices as an audit trail before deletion.

## Session 6 Preview — What Comes Next

| **📘 Session 6: Bindings, Navigation & Styling**                                                                                                       |
|--------------------------------------------------------------------------------------------------------------------------------------------------------|
| With business logic in place, Session 6 focuses on the presentation layer — making the application look and navigate well.                             |
| Bindings: Connecting controls to properties and formula expressions (binding a label text to computed values).                                         |
| Navigation: Implementing the complaint_id navigation link — clicking a complaint ID in the list loads the detail screen for that specific complaint.   |
| Styling: Applying predefined style classes (status badge colours — OPEN=blue, INPROCESS=orange, etc.) and custom CSS classes to sections and controls. |
| By end of Session 6, the application will look and feel production-ready at the complaint list and detail level.                                       |
|                                                                                                                                                        |
