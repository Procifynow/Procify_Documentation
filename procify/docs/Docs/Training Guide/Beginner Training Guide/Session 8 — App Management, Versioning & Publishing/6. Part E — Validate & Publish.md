# Part E — Validate & Publish

## E.1 — Validate vs. Publish — What's the Difference?

| **Action** | **What It Does**                                                                              | **When to Use**                                                                                   |
|------------|-----------------------------------------------------------------------------------------------|---------------------------------------------------------------------------------------------------|
| Validate   | Scans the application for errors WITHOUT building. Safe — nothing changes in the running app. | Run first, every time. Fix all errors before triggering Publish.                                  |
| Publish    | Validates first, then builds the app if no blocking errors exist. Updates the running app.    | After Validate passes with 0 errors. Use Full Build for first publish or after VH Config changes. |

## E.2 — Common Publish Blockers

| **Blocker**                               | **Cause**                                             | **Fix**                                                                              |
|-------------------------------------------|-------------------------------------------------------|--------------------------------------------------------------------------------------|
| VH Config not visible in UI after Publish | VH Config changes require a Full Build.               | Always select 'Full Build' for the first publish or after adding/editing VH Configs. |
| TypeScript compilation error              | Syntax error in entity .ts or controller .ts file.    | Open VS Code → check terminal for tsc errors → fix, save, re-validate.               |
| Update Schema not run                     | Entity properties added but schema not updated in DB. | Data Studio → select entity → Update Schema → confirm success toast.                 |
| Another build IN-QUEUE                    | A previous build is already running.                  | Click 'Proceed' to queue behind the current build. Do NOT cancel it.                 |
| Missing app_util flavor                   | Build & Deploy menu not visible.                | Ask trainer — app_util must be assigned to your developer account.                   |

## E.3 — Step-by-Step: Build & Deploy

| **1** | Open Build & Deploy<br/>Hamburger menu (☰) → App Builder → Build & Deploy.<br/>(If this menu item is missing, app_util flavor is not assigned to your account. Ask the trainer.) |
|---|---|
| **2** | Enter the Application<br/>In the App field, type customer_complaints_&lt;prid&gt; and press Enter.<br/>The application version details load. |
| **3** | Run Validate First<br/>Select Action: Validate.<br/>Click Submit.<br/>Wait for the validation report to generate.<br/>Download the XLSX report if errors are listed.<br/>Fix every ERROR before proceeding. Warnings can be reviewed but do not block the build. |
| **4** | Fix All Errors<br/>For each error in the report:<br/>- Missing Update Schema → Data Studio → Update Schema on the entity.<br/>- TypeScript error → VS Code → fix tsc error → save → re-validate.<br/>- Missing VH Build → select Full Build in the next step.<br/>Re-run Validate until the report shows 0 errors. |
| **5** | Run Publish<br/>Select Action: Publish.<br/>Build Type: Full Build (required for first publish and after any VH Config changes).<br/>Click Submit.<br/>The Publish Log shows the progression:<br/>IN-QUEUE → IN-PROCESS → PUBLISHED<br/>Do NOT navigate away while the build is running. |
| **6** | Verify the Published App<br/>Log out completely.<br/>Log back in.<br/>Open the hamburger menu → confirm 'Complaints' item is visible.<br/>Navigate to p_complaints → confirm live data loads.<br/>Verify: status badges render, VH dropdowns populate, all tabs in detail section work. |
