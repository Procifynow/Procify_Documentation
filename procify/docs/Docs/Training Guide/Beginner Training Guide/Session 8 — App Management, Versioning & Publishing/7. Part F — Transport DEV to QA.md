# Part F — Transport: DEV to QA

## F.1 — How Transport Works

Transport is a PULL mechanism: the TARGET system (QA) asks the SOURCE system (DEV) for the latest published version. You perform ALL transport steps while logged into the QA environment, not DEV.

| **Stage**     | **What Happens**                                                                          |
|---------------|-------------------------------------------------------------------------------------------|
| Setup         | Transport creates entries in QA metadata tables for the application, groups, and flavors. |
| Download      | Application ZIPs are pulled from DEV and extracted in the QA server's file system.        |
| Update Schema | Database tables for all entities are created or altered in the QA database.               |
| Finalising    | Application is set to ACTIVE in QA so users can log in and access it.                     |

| **⚠ Important**<br/>Transport Pre-requisites — verify ALL before starting<br/>1. The application must be in RELEASED status on the DEV system.<br/>2. Branch flavors CANNOT be transported. Create a new version, merge, then transport.<br/>3. The QA server's config.json must have mm_klo_online_server pointing to the DEV landscape URL.<br/>4. A host file entry for the DEV system must exist on the QA server.<br/>5. The transport_1 app must be assigned to the developer account on the QA system.<br/>If any pre-requisite is missing, the transport will fail at Setup or Download stage. Ask the trainer to verify the QA environment config before proceeding. |
|---|

## F.2 — Step-by-Step: Transporting to QA

| **1** | Log in to the QA System<br/>Open the QA environment URL in a browser (trainer provides the URL).<br/>Log in with your developer credentials.<br/>⚠ ALL remaining steps are done on QA, not on DEV. |
|---|---|
| **2** | Navigate to App Migration<br/>Hamburger menu (☰) → Deployment Center → App Migration.<br/>The App Migration screen lists all available applications from the connected DEV system. |
| **3** | Find Your Application<br/>In the list, locate customer_complaints_&lt;prid&gt;.<br/>If not visible, toggle the 'Show All' button to see all available apps (not just those with pending updates). |
| **4** | Click the App Row<br/>Click on customer_complaints_&lt;prid&gt;.<br/>A detail panel opens showing available versions from DEV and any already-installed versions in QA. |
| **5** | Install As Writable<br/>Click the available version update.<br/>A dialog appears with two options:<br/>As Readable — locked, cannot edit in QA.<br/>As Writable — editable, allows continued development in QA.<br/>Click 'As Writable' (recommended for training so you can fix issues in QA if needed). |
| **6** | Accept Conditions and Proceed<br/>A mandatory conditions dialog appears.<br/>For each mandatory item (⚠ icon), tick the acceptance checkbox.<br/>If prompted about shared flavor movement (on QA/PROD systems), click Proceed.<br/>Click Proceed to start the transport. |
| **7** | Monitor Transport Stages<br/>The screen shows progress through: Setup → Download → Update Schema → Finalising.<br/>Wait for each stage to complete. The overall status changes to ACTIVE when done. |
| **8** | Assign Users in QA<br/>After transport, the app is ACTIVE in QA but has NO users assigned.<br/>Go to Procify Workspace Hub → My Apps → customer_complaints_&lt;prid&gt;.<br/>Go to Roles &amp; Users tab → assign:<br/>emp_&lt;prid&gt; → Employee role<br/>mgr_&lt;prid&gt; → Manager role<br/>it_&lt;prid&gt; → ResponsibleTeam role<br/>Your developer account → Manager role |
| **9** | Verify in QA<br/>Log out of the QA developer session.<br/>Log in as emp_&lt;prid&gt; in QA.<br/>Verify: hamburger menu shows 'Complaints', p_complaints loads, all VH dropdowns work.<br/>Repeat with mgr_&lt;prid&gt; and it_&lt;prid&gt;. |

| **📘 Reference / Tip**<br/>Transport User Guide: Transport-_User_Guide.docx<br/>The Transport tool supports DEV → QA, QA → PROD, and DEV → DEV movement.<br/>Script Library (second tab in Transport screen) shows automated scripts maintained for the system — ask trainer if any scripts need to be run after transport. |
