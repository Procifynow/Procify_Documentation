# Part C — App Status Lifecycle & Versioning

## C.1 — App Status Values

Every version of an application on the Procify platform has a Status that controls what operations are allowed on it. Understanding these statuses is essential before releasing or transporting.

| **Status** | **Meaning**                                            | **Can Develop?** | **Can Transport?** | **Can Create New Version?**   |
|------------|--------------------------------------------------------|------------------|--------------------|-------------------------------|
| ACTIVE     | Current working version. All development happens here. | ✅ Yes           | ❌ No              | ❌ No                         |
| RELEASED   | Development complete and locked. Ready for transport.  | ❌ No            | ✅ Yes             | ✅ Yes (create from RELEASED) |
| DEPRECATED | Retired. Superseded by a newer version.                | ❌ No            | ❌ No              | ❌ No                         |
| DISCARDED  | Abandoned branch/version. Excluded from main path.     | ❌ No            | ❌ No              | ❌ No                         |

| **⚠ Important**<br/>Critical Versioning Rules — memorise these before proceeding<br/>A NEW VERSION can only be created from a RELEASED version.<br/>A BRANCH can only be created from an ACTIVE version.<br/>Branch flavors CANNOT be transported. Merge the branch into a new version first, then transport.<br/>Once status is changed to RELEASED, no further development is possible on that version.<br/>Always build (Validate &amp; Publish) BEFORE changing status to RELEASED. |
|---|

## C.2 — Step-by-Step: Releasing the Application

| **1** | Navigate to Procify Workspace Hub (also called Workspace Hub)<br/>Open the hamburger menu → Deployment Center → Procify Workspace Hub (or Workspace Hub).<br/>Alternatively: Hamburger menu → My Apps (if visible in your role). |
|---|---|
| **2** | Find Your Application<br/>In the Apps list, search for customer_complaints_&lt;prid&gt;.<br/>Click the App ID to open the application detail screen. |
| **3** | Open Edit Mode<br/>Click the Edit button (pencil icon ✏) in the toolbar.<br/>The Status field becomes editable. |
| **4** | Change Status to RELEASED<br/>In the Status dropdown, select RELEASED.<br/>Read the confirmation message carefully — this action locks all development on this version.<br/>Click Save.<br/>The app status changes to RELEASED. The Edit icon in Data Studio and Page Builder will now be disabled for this version. |
| **5** | Verify<br/>In the App detail, the Status badge shows RELEASED.<br/>Open Data Studio → select customer_complaints_&lt;prid&gt; → click the Edit icon.<br/>You should see a message that the app is locked for editing. |
