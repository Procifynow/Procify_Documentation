# Part C — Formatter Functions

A formatter function is a TypeScript method in the controller file that takes one or more raw model values as input and returns a formatted display value. It is the right tool whenever expression binding would become too long, needs multi-step logic, or needs to look up external data.

### C.1 — Where Formatter Functions Live

Formatter functions are public methods on the controller class. They must be public — the framework calls them reflectively from the Page Builder binding.

export class p_complaints extends KloController \{

// Formatter functions — called from Parts binding in Page Builder

public formatPriority(priority: string): string \{

const map: Record\<string,string\> = \{

'LOW': '🟢 Low', 'MEDIUM': '🟡 Medium',

'HIGH': '🔴 High', 'VERY_HIGH': '🚨 Very High'

\};

return map\[priority\] \|\| priority \|\| '—';

\}

\}

### C.2 — Formatter Function Examples for the Complaints App

| **Function Name**                 | **Input Parts**                                                 | **Return** | **Example Output**    |
|-----------------------------------|-----------------------------------------------------------------|------------|-----------------------|
| formatPriority(priority)          | \{\$M\>/detail/priority\}                                         | string     | 🔴 High               |
| formatTAT(actual, standard)       | \{\$M\>/detail/actual_tat\}, \{\$M\>/detail/standard_tat\}          | string     | ⚠ Overdue by 3 day(s) |
| formatStatusLabel(status)         | \{\$M\>/detail/s_status\}                                         | string     | 🟠 IN PROCESS         |
| formatFullName(first, last)       | \{\$M\>/detail/created_by_first\}, \{\$M\>/detail/created_by_last\} | string     | John Doe              |
| formatEscalationText(isEsc, type) | \{\$M\>/detail/is_escalated\}, \{\$M\>/detail/complaint_type\}      | string     | ESCALATED — BILLING   |
| formatDateAge(createdOn)          | \{\$M\>/detail/created_on\}                                       | string     | 3 days ago            |

### C.3 — Wiring a Formatter Function: Complete Steps

| **\#** | **Action**                          | **Detail**                                                                                                                                                                        |
|--------|-------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| 1      | Write the function in controller.ts | Open the controller file in Code Browser. Add a public method with the formatter logic. Ensure it takes the exact number of parameters as the number of Parts you will add. |
| 2      | Select the target control           | Page Builder → select the control whose display property you want to format (e.g. m.Text for priority display).                                                                   |
| 3      | Delete existing Path binding        | If a Path binding exists on the property, clear it first — Parts and Path cannot coexist.                                                                                         |
| 4      | Switch to Parts                     | Properties tab → click Parts radio button.                                                                                                                                        |
| 5      | Add each Part in order              | Click + for each model path. Order matters: Part 1 = first function argument, Part 2 = second argument, etc.                                                                      |
| 6      | Set Formatter Function field        | Type the exact function name as it appears in the controller. No parentheses, no 'this.' prefix.                                                                                  |
| 7      | Private Node must be running        | Formatter function calls go to the running Private Node. Start your Private Node before testing. Without it, the binding silently returns undefined.                              |
| 8      | Save and Full Preview               | The control should now render formatted output. Open Chrome DevTools Sources to debug if the output is wrong.                                                                     |

⚠ Formatter functions must be PURE — they should not modify model state, call APIs, or have side effects. They are called repeatedly on every model refresh. Side effects cause unpredictable behavior and performance issues.
