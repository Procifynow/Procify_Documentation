# Part C — Workspace Hub: Apps & Roles

### What Is an Application in Klobase?

An application is a self-contained unit that holds all the metadata you build — entities, queries, pages, menus, and more. It is the primary organising structure of everything you will do in Sessions 2–8. Users are assigned to applications (with roles), not to individual Pages or features.

### Creating the Customer complaint Application

| **1** | **Navigate to Apps**<br/>In the Workspace Hub, click Apps in the left navigation. |
|---|---|

| **2** | **Click Create New App**<br/>Click the Add button. The application creation form opens. |
|---|---|

| **3** | **Fill in Application Details**<br/>Complete the fields as shown in the table below. |
|---|---|

| **Field**              | **What to enter**                               |
|------------------------|-------------------------------------------------|
| App ID                 | Change the App ID according to the application  |
| App Name               | Same as app id                                  |
| Description (optional) | Service Request Management training application |

| **4** | **Save the Application**<br/>Click Save. The app appears in the Apps list with Active status. |
|---|---|

### Understanding Roles

Roles control what a user can do inside the application. Procify has two categories:

| **Role Type**              | **What it controls**                                                                                                                            |
|----------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------|
| System Roles (built-in)    | MANAGER,DEVELOPER and TESTER— control access to dev tools (data studio,page builder, Workspace Hub, Private Node). Pre-built into the platform. |
| Application Roles (custom) | Roles you define inside your app. Control what users see and can do at runtime within your app's Pages and data.                                |

For this training, define single application role inside your app:

| **Role Name** | **Precedence** | **Role Name** |
|---------------|----------------|---------------|
| DeliveryAgent | 1              | DeliveryAgent |

| **Role Precedence — Key Rule** • Precedence is a number. Lower number = higher priority. <br/> If a user has multiple roles, the one with the lowest precedence number takes effect at runtime. <br/> Delivery Admin(1) always overrides Delivery Agent(2) for a user assigned both roles. <br/> Your developer account will be Delivery Admin. The test user will be SRM_User. This lets you test both personas. |
|---|

### Creating the DeliveryAgent Role

| **1** | **Open Your Application**<br/>In the Apps list, click on srm_&lt;prid&gt; to open its detail screen. |
|---|---|

| **2** | **Go to Roles &amp; Users**<br/>Click on the Roles &amp; Users tab inside the application detail. |
|---|---|

| **3** | **Create the DeliveryAgent Role**<br/>In Application Roles, click Add. Role Name: DeliveryAgent.. Description: Field delivery personnel — can view and manage assigned deliveries. Click Save. |
|---|---|

| **4** | **Verify Roles Are Listed**<br/>Delivery Agents appear in the Application Roles list. |
|---|---|
