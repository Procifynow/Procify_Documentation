# Part F — Creating the d_complaints Entity and Initial Page Using the Wizard

Now that you understand what Procify eliminates, you will experience it firsthand. You will create the d_complaints entity and its Complaints list screen — using the Page Wizard — in this session. Session 2 will rebuild the same screen step-by-step so you understand every level of the hierarchy.

### F.1 — Open the Data Studio

| 1   | Log in to the platform as your developer account.                                                   |
|-----|-----------------------------------------------------------------------------------------------------|
| 2   | From the main menu, expand Design Studio → select Data Studio.                                      |
| 3   | In the application dropdown at the top of the tree, select your app: customer_complaints\_\<prid\>. |
| 4   | The tree is currently empty. You will add d_complaints now.                                         |

### F.2 — Create the d_complaints Entity

| **⚠ Naming rules — read before creating anything**<br/>Only lowercase letters, numbers, and underscores. No spaces, hyphens, or capitals.<br/>IDs cannot be changed after creation — a wrong name requires deleting and recreating.<br/>Never use "user" as an entity ID — reserved keyword in MySQL.<br/>d_ prefix = Runtime Entity — always use this prefix for transactional entities. |
|---|

| 1                           | Click the + button in the tree → select Entity. The entity creation dialog opens.                                       |
|-----------------------------|-------------------------------------------------------------------------------------------------------------------------|
| 2 | Entity ID: d_complaints. Click Create.                                                                                  |
| 3                           | When prompted for the Primary Key — Property ID: complaint_id \| Kind: Primary \| Data Type: Auto Number. Click Submit. |
| 4                           | Click Save. d_complaints appear in the left tree.                                                                       |

### F.3 — Add All Properties to d_complaints

Follow the steps below to add each property. The complete property reference table is in Part A.

| **1** | Click on d_complaints in the tree to select it.                                                       |
|-------|-------------------------------------------------------------------------------------------------------|
| **2** | Click on the Properties tab in the detail panel.                                                      |
| **3** | Click the + button to add a new property. The qualifier selection menu opens.                         |
| **4** | Select the qualifier (Regular for most properties) → fill in Property ID, Data Type, and Short Label. |
| **5** | Toggle key attributes where required: ❗ Mandatory for complaint_desc.                                |
| **6** | Click Save after each batch of properties.                                                            |
| **7** | Repeat for all 20 properties listed in the d_complaints table in Part A.                              |

| **⚠ Data type reminder**<br/>Use Text (not String) for complaint_desc and remark — they exceed 255 characters.<br/>Use Timestamp for all date fields: first_response_date, planned_resolution_date, closed_on, created_on, modified_on.<br/>Use Boolean for is_escalated — not String.<br/>Use Decimal for actual_tat and standard_tat. |
|---|

### F.6 — Create the Complaints Page Using the Wizard

The Page Wizard creates a full working screen — with page, layout, area, section, and controls — in a few clicks. Use it now to produce your first Complaints screen quickly. In Session 2 you will build the same screen manually, step-by-step, so you understand every level.

| **1** | From the main menu, open Page Builder (under Design Studio).                                                                                             |
|-------|----------------------------------------------------------------------------------------------------------------------------------------------------------|
| **2** | In the application dropdown, select customer_complaints\_\<prid\>.                                                                                       |
| **3** | Click the Edit icon → click the + icon → select Create Page from Wizard.                                                                                 |
| **4** | Page ID: p_complaints \| Title: Complaints \| Lead Entity: d_complaints. Click Next.                                                                     |
| **5** | Select the page template: List & Detail (this generates a search bar, a card list, and a detail form).                                                   |
| **6** | In the entity property selection screen, tick all properties you want on the list card: complaint_id, complaint_desc, priority, assigned_to, created_on. |
| **7** | In the detail form selection, tick all properties. Click Generate.                                                                                       |
| **8** | The wizard creates the full page hierarchy automatically. Click Save.                                                                                    |
| **9** | Click Show Full Preview to verify the three test complaint records appear as cards in the list.                                                          |

| **📘 What the wizard created**<br/>Page: p_complaints (with route /complaints)<br/>Page Layout: pl_complaints_desk (Stack type)<br/>Page Area: pa_complaints (assigned to the layout)<br/>Section: s_complaint_search (Search type — for filtering)<br/>Section: s_complaint_list (CardList type — shows all complaints)<br/>Section: s_complaint_detail (Form type — shows one selected complaint)<br/>All controls bound to the correct d_complaints properties automatically.<br/>In Session 2 you will understand every one of these elements and rebuild it from scratch. |
|---|

## Session 1 Assignment

Complete all mandatory tasks before Session 2. The trainer will verify each item at the start of Session 2 before proceeding.

### Mandatory Tasks

1\. Create the application customer_complaints\_\<prid\> in the Workspace Hub.

2\. Create three roles: it_employee (prec 3), employee_manager (prec 2), it_team (prec 1).

3\. Create three test users: emp\_\<prid\>, mgr\_\<prid\>, it\_\<prid\>.

4\. Assign emp\_\<prid\> → it_employee. Assign mgr\_\<prid\> and your developer account → employee_manager. Assign it\_\<prid\> → it_team.

5\. Verify all three test users can log in (incognito windows) and see the application.

6\. created a d_complaints entity with all 20 properties. Update Schema → success toast confirmed.

7\. Create 3 test complaint records using the Data Browser.

8\. Create page p_complaints using the Wizard. Verify 3 cards visible in preview.

9. Create a Team Group (grp_response_team\_\<prid\>) with at least two of your test users as members, link it to the app’s App Collection, and verify both members can see the application without being assigned individually.
