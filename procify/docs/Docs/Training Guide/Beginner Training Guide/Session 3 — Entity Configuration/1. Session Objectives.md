# Session Objectives

By the end of this session, you will be able to:

- Understand what Entity Relations are and create Primary and Non-Primary (Aggregated) relations between entities.

- Understand what Object Types are, why they are needed, and configure complaint type classifications for d_complaints.

- Configure Status and Status Groups to represent the complaint lifecycle (OPEN → INPROCESS → ON HOLD → RESOLVED → CLOSED → REOPEN).

- Set up an ID Series for complaint_id to auto-generate readable complaint numbers (e.g. CMP-00001).

- Update the p_complaints UI to reflect the new entity configuration — making the complaint_type, status, and complaint_id fields work correctly in the page.

| **📘 What This Session Builds On**                                                                                                                       |
|----------------------------------------------------------------------------------------------------------------------------------------------------------|
| Session 1 created the application, roles, users, and d_complaints entity with raw properties.                                                            |
| Session 2 created the remaining 5 entities and built the full p_complaints page step by step.                                                            |
| Session 3 enriches the d_complaints entity with the platform features that turn raw fields into intelligent, lifecycle-aware data.                       |
| After Session 3, the complaint_id will auto-generate, the status dropdown will show the correct lifecycle values, and complaint_type will be classified. |
|                                                                                                                                                          |
