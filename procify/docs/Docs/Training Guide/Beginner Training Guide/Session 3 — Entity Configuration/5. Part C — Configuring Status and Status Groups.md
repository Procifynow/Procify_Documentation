# Part C — Configuring Status and Status Groups

## C.1 — What Is Status in Klobase?

The system property s_status represents the current state of a complaint record. The Status tab in the Data Studio lets you define the allowed values for s_status and group them into Status Groups.

Status Groups are named collections of statuses. They are used in Vienable (Session 7) to control screen behaviour: for example, the Edit button is visible only when s_status is in the OPEN_GROUP, and the Assign Team button is visible only when s_status is in the INPROCESS_GROUP.

| **📘 Status Lifecycle for Customer Complaints**                                                                                        |
|----------------------------------------------------------------------------------------------------------------------------------------|
| The complaint lifecycle defined in the BRD has 6 states:                                                                               |
| OPEN → INPROCESS → ON_HOLD / RESOLVED → CLOSED / REOPEN                                                                                |
| Each status transition is triggered by a specific role (defined in the Role Responsibility matrix from Session 1 Part A).              |
| In this session you define the status values and groups. The actual UI enforcement of transitions using Vienable happens in Session 7. |
|                                                                                                                                        |

## C.2 — Status Values and Groups to Configure

| **Status ID** | **Short Label** | **Status Group** | **Triggered By**                               |
|---------------|-----------------|------------------|------------------------------------------------|
| OEN           | Open            | OPEN             | Auto-set on complaint creation by Employee     |
| INPROCESS     | In Process      | INPROCESS        | Manager assigns responsible_team               |
| ON_HOLD       | On Hold         | INPROCESS        | Responsible Team puts on hold                  |
| RESOLVED      | Resolved        | ACCEPTED         | Responsible Team / Manager marks resolved      |
| CLOSED        | Closed          | COMPLETED        | Manager confirms resolution and closes         |
| REOPEN        | Re-Opened       | OPEN             | Employee or Manager reopens a closed complaint |

## C.3 — Step-by-Step: Adding Status Values

| **\#** | **Action**             | **Detail**                                                                                                                                                                   |
|--------|------------------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **1**  | Go to Status tab       | Select d_complaints in the tree. Click the Status tab in the Detail panel.                                                                                                   |
| **2**  | Enable                 | Switch on the status and click save and edit                                                                                                                                 |
| **3**  | Add OPEN status        | Click the Add Record(+) icon. Fill: Status: OPEN \| Description: Open \| object_type: PROCIFY \| Status Group : OPEN. Click Save.                                            |
| **4**  | Add remaining statuses | Repeat Add for each status: INPROCESS (In Process), ON_HOLD (On Hold), RESOLVED (Resolved), CLOSED (Closed), REOPEN (Re-Opened) for PROCIFY. Click Save after all are added. |
|        | Repeat for MAVENTIC    | Repeat the Action 3 and 4 for object_type maventic as well.                                                                                                                  |
| **4**  | Verify list            | All 12 status values appear in the status list.                                                                                                                              |

| **💡 Why Status Groups Are Important for This Application**                                                  |
|--------------------------------------------------------------------------------------------------------------|
| Session 7 will use these groups to configure Vienable on buttons and fields.                                 |
| Example: The 'Edit' button will be configured as: Visible only when s_status_group = OPEN_GROUP.             |
| Example: The 'Assign Team' button will be: Visible only when s_status_group = OPEN_GROUP and Role = Manager. |
| Without the groups defined now, the Vienable configuration in Session 7 cannot be done.                      |
|                                                                                                              |
