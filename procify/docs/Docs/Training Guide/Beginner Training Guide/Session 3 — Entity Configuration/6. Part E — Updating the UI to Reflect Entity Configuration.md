# Part E — Updating the UI to Reflect Entity Configuration

Now that d_complaints has Relations, Object Types, Status values, and an ID Series configured, the p_complaints page must be updated to expose and use these configurations. In this part you will:

- Add Relation-based TransNodes to p_complaints for d_complaint_item, d_complaint_voices, and d_complaints_attachment.

- Connect the s_complaint_item grid (already in the pa_comp_details tab from Session 2) to the d_complaint_item relation TransNode.

- Verify the complaint_id field auto-populates from the ID Series.

- Verify the s_status field on the search section and the detail form is bound and showing the correct status values.

| **📘 Why the UI Needs to Be Updated**                                                                                                                                                        |
|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| When you added Relations in Part A, the platform can now automatically fetch child records. But the Page Builder still needs to be told WHICH TransNode to use to access that relation data. |
| A Relation-type TransNode in the Page Data Model references the relation name (pr_complaint_item) and automatically joins child records to the active parent complaint record.               |
| The complaint_id field in the form section can now be set to read-only since the ID Series will fill it — the user should not manually enter a complaint ID.                                 |
|                                                                                                                                                                                              |

## E.1 — Add Relation TransNodes to the Page Data Model

| **\#** | **Action**                       | **Detail**                                                                                                                                                |
|--------|----------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------|
| **1**  | **Open Page Builder**            | Navigate to Design Studio → Page Builder. Select customer_complaints\_\<prid\>. Click the Edit icon to enable edit mode.                                  |
| **2**  | **Select p_complaints**          | Click p_complaints in the tree. Open the Page Data Model panel (right-side tab).                                                                          |
| **3**  | **Review existing TransNodes**   | You should see: search (Query), list (EntitySet / Transfer&Link from search), detail (Entity / Transfer&Link from list). These were created in Session 2. |
| **4**  | **Add complaint item TransNode** | Click the detail transnode → click + icon available next to r_complaint_item in unused properties. Fill: Path: complaint_items                            |
| **6**  | **Repeat**                       | Repeat Action 4 for relation voices, attachments                                                                                                          |
| **7**  | **Save**                         | Click Save.                                                                                                                                               |

## E.2 — Wire the s_complaint_item Section to the Relation TransNode

Need to create a s_complaint_item, s_complaint_voices, s_complaint_attachments section with screen_type as grid and bind with respective transnode.

| **#** | **Action** | **Detail** |
|---|---|---|
| **1** | Create s_complaint_item | Right-click pa_complaint_details → new → section → right click section → rename : s_complaint_item |
| **3** | Mark type as section | Add type = section for s_complaint_items layout |
| **2** | **Open Detail panel** | Click s_complaint_item to open its Detail properties on the right. And fil title = items |
| **3** | **Set TransNode path** | In the TransNode/Path field, set: complaint_items. This references the relation TransNode created in E.1 Step 4. |
| **4** | **Add controls** | Right-click s_complaint_item → New → Controls. Add: item_id, product, issue_observed. Or drag from Page Data Model → d_complaint_item → Unused Properties. |
| **5** | **Set screen type** | Confirm s_complaint_item screenType = grid. Set showTitle = true so the tab label 'Complaint Items' is visible. |
| **6** | **Add Section Toolbar** | Right click on s_complaint_item → New → Toolbar<br /> Add and Delete buttons will be added to section if not enable showAdd and showDelete properties as true |
| **7** | **Add Save Button** | Right click on the section toolbar → Action/Items → update text → add press event and select save from vh. |
| **8** | **Add config** | Right click- s_complaint_item → new → config<br/>Add visibleRowCountMode = Fixed \| visibleRowCount = 5 |

Repeat the same for s_complaint_voices and s_complaint_attachments as well with respective transnodes.

## E.4 — Verify s_status in Search and Detail Sections

The s_status field is a system property. Now that Status values are configured in the Procify Data Studio (Part C), the status dropdown in the search section and detail form will automatically render the configured values (OPEN, INPROCESS, ON_HOLD, RESOLVED, CLOSED, REOPEN).

| **#** | **Action** | **Detail** |
|---|---|---|
| **1** | **Click Show Full Preview** | Add the property in s_search and s_complaint_detail and In the Page Builder, click Show Full Preview to load live data. |
| **2** | **Verify s_status in search bar** | In the search filter bar, click the Status dropdown. Verify the 6 status values appear: OPEN, INPROCESS, ON_HOLD, RESOLVED, CLOSED, REOPEN. |
| **3** | **Click a complaint row** | Select any complaint record from the list. The detail area loads. |
| **4** | **Verify complaint_id** | 1. For creating complaints with object_type enable **showAddWithObjectType** option for s_complaint_list section toolbar.<br /> 2. The complaint_id field should show the P-00001 or M-0001 format based on object_type (or different if the test record was created before the ID Series was set up — create a new record to confirm). |
| **5** | **Verify Complaint Items tab** | Click the Complaint Items tab in the pa_comp_details area. If the selected complaint has items, they should appear in the grid. The tab was empty in Session 2 — it should now have a data source. |
