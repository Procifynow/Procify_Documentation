### **Part C — TransNode onArrive & navigateId**

### **Configuring onArrive on a TransNode (Model Path)**

onArrive is a property of a TransNode/model path that controls what data (if any) gets set when the parent's data arrives — and whether that propagates to the folded (child) path.

#### **Implementation Steps**

1.  **Create or select the model path** — in Procify Page Builder, click **Add** on the model tree toolbar (or select an existing transnode) and choose its path name, node type (Entity, Entity Set, Query, or Other), and the entity/query ID.

2.  **Open the transnode's detail section** and locate the **onArrive** field alongside the other model path properties (folded_from, node_type, set_active_if, etc.).

3.  **Choose the onArrive value** based on the behavior you need:

    - **Blank** — data is set to the path itself, but *not* propagated to its folded (child) path.

    - **First** — the 0th index of the parent entityset is automatically set active for this transnode.

    - **History** — the previously active index (per unique key) is restored as active when the user returns to this path; this only applies to entityset-type transnodes.

    - **None** — no data is set on this transnode or its folded child at all.

4.  **Pair it with set_active_if navigation validation matters.** If set_active_if is set to **Valid** (the default), the framework checks for dirty/invalid objects on navigation and — if onArrive conditions are met — calls the onValidate hook in the entity's \<entity_name\>.ts file to enforce validation before allowing the transition.

5.  **Verify parent-child propagation behavior**, since onArrive also governs how data cascades between transnode types:

    - Entity/Entityset parent → Query child: the query tied to that entity/entityset is set.

    - Query parent → Entityset child: the query's held entityset is set.

    - Query parent → Entity child: the 0th index of the query's entityset is set.

    - Entityset parent → Entity child: the passed index is set, or — if no index is passed — the index is resolved based on the onArrive value (First/History/None/Blank).

6.  **Test navigation flows** (forward and backward) to confirm the right index/data is restored — this is especially relevant for **History**, which is the mode that makes list→detail navigation "remember" the last selected row.
