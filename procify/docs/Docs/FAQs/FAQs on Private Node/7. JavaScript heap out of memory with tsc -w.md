# JavaScript heap out of memory with tsc -w

**Q: I'm getting a "JavaScript heap out of memory" / "FATAL ERROR: Ineffective mark-compacts near heap limit" error when running tsc -w in Private Node. What's causing this and how do I fix it?**

**A:** This typically happens when your system doesn't have enough free RAM left for the TypeScript watcher to allocate memory — often because browsers (Chrome/Edge) or other applications are already consuming most of the available memory. On an 8GB machine, it's common to see 7GB+ already in use before the compiler even starts.

**Immediate fix:**

- Close unused browser tabs/windows and other memory-heavy applications before starting a tsc -w session.

Alternatively, give Node a defined heap budget so it fails more gracefully or succeeds where the default limit was too aggressive:
set NODE_OPTIONS=--max-old-space-size=4096 tsc -w

-

**If the issue persists or recurs frequently:**

- A RAM upgrade (16GB recommended) is advised for machines regularly running Private Node builds alongside browsers/IDEs.

- Check that tsconfig.json includes incremental: true and skipLibCheck: true to reduce the compiler's memory footprint per rebuild.

- Use cmd terminal to start the typescript watcher (tsc -w).
