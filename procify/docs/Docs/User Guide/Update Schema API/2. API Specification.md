# API Specification

API name: createTable

Method: GET

## Parameters

There are four levels of schema update, the parameters guide for each level type is mentioned below:

#### Flavor Level

> This is for updating all the tables of one/multiple flavors.
>
> Mandatory Parameters: **update_level**, **landscape**, **fv_list**, **consider**
>
> Optional params: **log_required**, **force_uncompatible, is_config**
>
> **\{**
>
> **//@mandatory**
>
> **update_level: "flavor",**
>
> **//@mandatory**
>
> **landscape: "tools_dev6",/\* Landscape ID \*/**
>
> **//@mandatory**
>
> **consider: "table",/\* "table" or "index" \*/**
>
> **//@mandatory**
>
> **fv_list: \[\{fl:'eam',ver:'1'\}\], /\* multiple flavors are also allowed but the sequence has to be maintained properly (parent,child)\*/**
>
> **//@optional**
>
> **log_required: false,/\* true or false\*/**
>
> **//@optional**
>
> **force_uncompatible: false,/\* true or false\*/**
>
> **//@optional**
>
> **is_config: false,/\* true or false. If true, then it considers config entities(Metadata DB) \*/**
>
> **\}**

#### Entity Level

> This is for updating the table of only one entity.
>
> Mandatory Parameters: **update_level**, **landscape**, **fv_list**, **entity_name**
>
> Optional params: **log_required**, **force_uncompatible, give_diff, is_config**
>
> **\{**
>
> **//@mandatory**
>
> **update_level: "entity",**
>
> **//@mandatory**
>
> **landscape: "tools_dev6",/\* Landscape ID \*/**
>
> **//@mandatory**
>
> **entity_name: "d_no_header",/\* entity name \*/**
>
> **//@mandatory**
>
> **consider: "table",/\* table or index\*/**
>
> **//@mandatory**
>
> **fv_list: \[\{fl:'eam',ver:'1'\}\], /\* pass only one belonging flavor in the array \*/**
>
> **//@optional**
>
> **log_required: "FALSE",/\* "TRUE" or "FALSE" \*/**
>
> **//@optional**
>
> **force_uncompatible: false,/\* true or false\*/**
>
> **//@optional**
>
> **give_diff: false,/\* true or false- This will return the difference between metadata and table in DB\*/**
>
> **//@optional**
>
> **is_config: false,/\* true or false- This flag indicates whether the selected entity is config or not\*/**
>
> **\}**

#### Index Level

>
> Optional params: **log_required**
>

> **//@mandatory**

> **landscape: "tools_dev6",/\* Landscape ID \*/**
>
> **//@mandatory**
>

> **//@mandatory**
>
> **consider: "index",**

> **//@mandatory**

> **fv_list: \[\{fl:'eam',ver:'1'\}\], /\* pass only one belonging flavor in the array \*/**
>
> **//@optional**
>
> **log_required: false,/\* true or false\*/**
>
> **\}**

#### Landscape Level

> This is for updating all the tables of a landscape.
>
> Mandatory Parameters: **update_level**, **landscape**, **consider**
>
> Optional params: **log_required**, **force_uncompatible**, **drop_extra, is_config**
>
> **\{**
>
> **//@mandatory**
>
> **update_level: "landscape",**
>
> **//@mandatory**
>
> **landscape: "tools_dev6",/\* Landscape ID \*/**
>
> **//@mandatory**
>
> **consider: "table",/\* "table" or "index" \*/**
>
> **//@optional**
>
> **log_required: false,/\* true or false\*/**

## NOTE

1.  **Table** and **Index** can not be processed at a time. The **‘consider’** flag has to be either **‘table’** or **‘index’**.

2.  For dropping additional tables and columns which are not used, createTable api has to be called at the **landscape level** and the **drop_extra** flag has to be **‘TRUE’**. API doesn't delete the tables/columns, it only **returns the deleted SQL statements**.

3.  **force_uncompatible** flag is for updating the column **domain/length** forcefully. It may result in **data truncation**. Use it wisely.

4.  The primary key change is allowed only in owning flavor.

5.  Domain, length, and precision change are not allowed in non-owning flavors.

6.  Entity scp (Scope/Persists on) needs to be maintained for creating table in server as well as in the client. If the scp is marked **both** it will create table in client and server side. scp marked as **client-only**, will create a table in client and scp **server-only** will create a table in server DB.

> **After changing the scp of the entity for server-side the changes will reflect no build will be required but in client to reflect the changes build is required.**

7.  Compatible changes are mentioned in the [sheet](https://docs.google.com/spreadsheets/d/1R9q02xgUj3yKylELajMxkEfC2cp3lFDek6W-prHaXiw/edit?usp=sharing), this list may change in future if required
