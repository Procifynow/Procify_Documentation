# Key mapping

Parent Key Mapping:

This is to auto populate the parent keys while creating an entity. Pass entity or JSON format on new entity creation. Keys are auto populated before save and accessible in UI controller and callbacks. Key gets populated upto N level in a BO. Object type is mandatory to pass. What if an entity does not have an object type?

In case if the object type is not passed, it will return with error.

ID series gets generated on entity create if applicable and populate the IDs to UI/Model. In case any child entity exists and ID is part of primary key, it populates to child entity also.

Mapping for already existing objects. Like two BPs are already created and map these as BP relation.

- Primary relation: If primary relation is maintained for two entities, keys get auto populate from parent. To understand this take an example of order creation. While adding a line item in order, order ID gets filled from header automatically.

- Aggregation: This is to populate the key in the entity which is not part of the same BO. Separate metadata input required if key mapping to be supported in aggregation relation. Or API to be provided.

Secondary key mapping:

This is to decide either to perform create or update operation on message received from Middleware.

For example, order ID is a primary key in order BO and map this with legacy ID as secondary key. While processing message from SAP this, if legacy ID already exists it perform update operation otherwise create operation.
