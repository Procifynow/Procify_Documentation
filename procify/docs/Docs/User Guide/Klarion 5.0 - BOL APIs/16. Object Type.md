# Object Type

Object Type defines the possible behaviour of an BO/Entity. Object type has a unique key and description. Object type key is unique across all entities and can not be reused across entities. One entity can store multiple objects data if behavior of the objects are different then define multiple object types.

Work when has_object_type is marked TRUE for an entity. Do not add any Entity property to add object type field this will be taken care by kloBase based on the Object type flag on Entity level.

- Possible object types for an entity has to be defined at design time and maintain via kloIDE.

- Data type is **int(11)**. Max value is 2147483648.

- Supports merging based on uses relation.

- s_object_type holds the object type key.

- Descriptions are part of value help definition.

Constants for Object Type.

- If the object type is false for an entity than -1 is reserved value.

**Abbreviation :** define object type abbreviation like ‘i’ for invoice and ‘o’ for order. This abbreviation can be used in ID series as prefix. Syntax: \$objecttype.abr

Variable to be used:

- Constants

- \$VARIABLE

**Display Messages:** Object type description supports translatable description use as substitute in title, message, etc with \$objecttype.dec. Define language dependent text to support multilocal.

**Create Entity:** while creating an Entity, Object Type has an important role to load the configuration, assign ID from ID series, Rule to be executed, VH to be loaded.

**Tuner**: configurations are maintained on object type to control the behaviour of the application. For more details please visit the [<u>Config</u>](#entity-configuration) section.

**Rule subscription:** rules are subscribed on Entity and Object Type.

**ID Series:** ID series can be defined on object type or common for all object types.
