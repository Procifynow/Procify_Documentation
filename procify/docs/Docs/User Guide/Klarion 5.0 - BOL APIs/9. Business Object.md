# Business Object

Business Object (BO) is a logical unit used in a business. It is made up of one or multiple entities. E.g. If we take an invoice (bill of purchase) it consists of header and purchased items. Header and item entities ( tables) are required to store this information. Either item or header alone does not make any sense. So invoice header and invoice item entity together makes the invoice BO.

BO is a hierarchical tree of entities. Each entity must belong to one and only one BO definition. BO has only one root entity (top level). Rest of the entity (child entity) are aggregated into root or other entities to construct the entity tree.

Root entity represents the BO, root entity name becomes the BO name. Root entity also takes the full responsibility as BO apart from it’s entity responsibility.There are BO rules which are executed on root entities only like EndPointResolver, Success/ Fail / message mapper etc.

kloBroker always transmits the full BO in the Message. When any entity becomes dirty it pulls parents till root within BO in writeset. Deletion of any entity instance deletes all the cascaded agrragaed entities instances.

Primary relations are used between entities to bundle to construct entities tree in BO. All participating instances are traversable by primary relation with in BO. and each object can be visited only once. Primary relation represents aggregation with 0..n cardinality. BO tree is made of entity as node and primary relation as connector.

In authorization all the authorization upon parents up to root are also applied except the middleware message process.

Example:

- d_order (root entity/BO)

  - d_order_item (child entity)

    - d_order_conditions (child entity)
