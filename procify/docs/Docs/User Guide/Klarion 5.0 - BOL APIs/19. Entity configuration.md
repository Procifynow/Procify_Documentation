# Entity configuration

Configuration is the manner in which components are arranged to make up the system or application. Configuration controls or changes the behaviour of the application.

- Possible set of configuration for an entity by which the process flow or behaviour is controlled.

- Configuration can decide the behaviour of UI, Some Validations, Object flow, etc

- Works when an entity is marked with has_config to true and configuration entity properties are maintained.

- Configuration is Object Type based. In case if no object type applicable to an Entity, default Object Type is -1.

- Entity configuration is framework controlled and values are filled through kloTuner.

- Metadata definition for configuration entity is provided through Procify Data Studio.

- config as a relation on runtime entity is provided automatically by framework when has_config is read true.

- entityObject.config will return you with a single row of the configuration maintained for this entity with respect to the current object this holds. If no object type is found / has object type is false, framework will try to find a default configuration with -1 as the default object type.

- If no configuration is found, returns an empty object.

Steps for configuration:

- Mark the entity(d_order) as “Has Config” in Procify Data Studio.

- Framework creates a Configuration Entity. It has is_config true and calculated from the entityname by replacing the first character to ‘c’. For example the main Entity is ‘d_order’ then configuration Entity gets created with the name of ‘c_order’.

- Add the properties in Procify Data Studio with new Entity for all configurations.

- Run Update schema to create a database table. One Entity has only one Config table with multiple configuration values for different Object types.

- Define the possible values allowed for a configuration property in Procify Data Studio. Each possible value has some meaning and definition or implication of that value also to be explained in detail. This help consultants to change the confuration.

- kloTunner facilitates the maintenance of the configuration. Maintain the config values for each configuration using kloTunner.

- Write business logic based on possible values of each configuration. Application behaviour can be changed either on UI or in APIs/Backend based on the configured value.

For Example, Sales Order has few configurations like:

- Credit Limit Check

- Free Goods

- Order Approval

- Order Close

- Manual header discount

- Manual Item discount

- Default Division

- Pricing Procedure

- ATP Check

- Expected Delivery Days

- Auto Back Order

- Group Order

- Part Delivery Allowed
