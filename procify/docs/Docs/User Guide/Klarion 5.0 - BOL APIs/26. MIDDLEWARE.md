# MIDDLEWARE

Middleware allows set of configuration on its functionalities.

## KeyMapping

## attachMessageProcessor deprecated

This method allows to attach a new message processor, A message processor is a class which intakes a downloaded message and builds the BO structure out of it and persist these BO/Entity.

When middleware starts processing the downloaded message from server, based on the download process count, messages are read and the message processor callback is invoked with the messages, Now then the MessageProcessor class is responsible to deal with the message and resolve when the message is processed or reject in case of error so that middleware can continue processing the next message and handle error on the current message.

By default Klarion BOL will attach a MessageProcessor class to handle the V4 middleware messages, in case the message processing has to be changed, attach a new MessageProcessor and encapsulate the logic to it only the expected return is a Promise and resolve or reject

Ex. **mw.attachMessageProcessor(function(messages)\{**

**return new MessageProcessor().process(messages);\})**

## attachConverter - deprecated

Allows to attach convertor callbacks, which has to be called before

1.  **BEFORE_ADD_TO_UPLOAD_Q**

2.  **BEFORE_PUSH_TO_SERVER_Q**

3.  **AFTER_PULL_FROM_SERVER_Q**

4.  **AFTER_LOAD_FROM_DOWNLOAD_Q**

These callbacks are called with the message object which can be morphed according to the application logic and the resultant message is considered by the framework.

Each callback is expected to return the morphed message, or a Promise and resolves with morphed message.

Each call back can get array of messages, call back should be able to handle this.

Ex: mw.attachConverter(AFTER_PULL_FROM_SERVER_Q,function(messages)\{

//manipulate and resolve or return data here

\})
