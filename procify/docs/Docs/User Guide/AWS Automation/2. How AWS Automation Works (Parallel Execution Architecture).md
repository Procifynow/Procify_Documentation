# How AWS Automation Works (Parallel Execution Architecture)

AWS automation now leverages high-performance EC2 instances to run multiple test suites in parallel using a simplified architecture. Instead of the previous hub-node Selenium Grid setup, the system provides dedicated Windows instances that directly execute automation tests in headless mode, maximizing resource utilization and reducing complexity.

**Key Components:**

- **Master Systems:** Two powerful Windows EC2 instances (c6a.8xlarge) each capable of running 15+ automation suites simultaneously.

- **Parallel Execution**: Each system runs multiple WebDriverIO test suites concurrently in headless Chrome mode.

- **Direct Browser Management**: Each automation directly manages its Chrome browser instance without requiring Selenium Grid coordination.

- **Pipeline**: Bitbucket pipeline that triggers AWS spin-up, parallel test execution, and teardown.

### What Is Happening End-to-End?

**1. Pipeline Triggered**: A Bitbucket pipeline is manually or automatically triggered with master1 or master2 configuration.

**2. Provision EC2 Instances:** The pipeline scripts launch Windows EC2 instances:

- Two high-performance Windows instances (c6a.8xlarge).

- Each instance configured with Chrome browser and automation dependencies.

**3. System Configuration:**

- Configure hosts file entries for application access.

- Set up an automation environment and extract project files.

**4. Parallel Test Execution:**

- Each Windows instance simultaneously runs 15+ automation suites.

- Tests execute in headless Chrome mode for optimal performance.

- No Selenium Grid - direct WebDriverIO to Chrome browser communication.

5\. **Concurrent Processing:**

- Master1 handles editor-related automations (Procify Workspace Hub, Procify Data Studio, Procify Page Builder).

- Master2 processes tools and other component automations.

6\. **Reporting and Cleanup:**

- Test reports and logs are generated and uploaded to S3.

- EC2 instances are terminated to optimize costs.
