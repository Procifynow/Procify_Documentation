# Usage

1.  onPageInit

    1.  This event will be called as soon as the controller is loaded. The transaction, model and UI are yet to be created for this controller when this event is called.

    2.  This event will be called only once.

2.  onPageModelReady

    1.  This event will be called when the model is created and the transnodes are initialized, but the Data is not set to the model yet. From this event, the developer can call the skipModelPreparation method which will skip setting the data and executing the query. If the developer skips the model preparation, then he/she should be responsible for setting the data in the model.

    2.  This event will also be called once.

3.  onPageEnter

    1.  This event will be called whenever the screen enters the visible area using navigation (Both front and back navigation). If the navigation is within the same screen, this event will not be triggered.

    2.  This event will be called after the data is set(if the model preparation is not skipped) to the model.

4.  onPageExit

    1.  This event will be called in the source screen whenever the developer navigates to a different screen.

    2.  The developer can call cancelNavigation API which will cancel the navigation.

5.  onPageDestroy

    1.  This event is called when the screen is destroyed. Destruction of the screen is initiated only during back navigation.

    2.  This event will be called only once.

All the events hold a read-only object as a parameter which holds information such as if the screen is initialized or not, if the navigation to the screen is from an external source or not, navigation parameters and source screen ID from where the navigation is triggered.
