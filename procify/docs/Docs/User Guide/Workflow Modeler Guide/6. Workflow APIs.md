# Workflow APIs

- WorkflowServices gives a supported API with the same rules as UWL (flavor scoping, user scope, group-candidate tasks).

- **Typical use:** a custom screen or service that shows a user’s pending approvals, lets them approve or reject, and tracks their submitted requests, without embedding the UWL screen.

### **What each method is for, with example usage**

The ticket doesn’t give signatures, so the calls below are illustrative only. Argument names and shapes are assumed. Check the JSDoc in WorkflowServices.ts for the real ones.

ts

const wf = WorkflowServices.gI("myFlavor", txn);



| **Method**               | **Used for**                                        | **Example**                                               |
|--------------------------|-----------------------------------------------------|-----------------------------------------------------------|
| gI(flavor, txn)          | Start here. Gets the service scoped to your flavor. | const wf = WorkflowServices.gI("myFlavor", txn);          |
| getTasksP                | A full worklist (open plus others) with filters     | await wf.getTasksP(\{ priority: "High" \})                  |
| getOpenTasksP            | A “Pending approvals” tab or badge count            | await wf.getOpenTasksP(\{\})                                |
| getEscalatedTasksP       | An “Escalated / overdue” tab                        | await wf.getEscalatedTasksP(\{\})                           |
| getHistoryTasksP         | A “Completed tasks” history view                    | await wf.getHistoryTasksP(\{ deadlineFrom: "2026-10-01" \}) |
| getTaskP                 | A task detail page                                  | await wf.getTaskP(taskid)                                 |
| getFilterOptionsP        | Filling filter dropdowns (workflow, priority)       | await wf.getFilterOptionsP()                              |
| getMySubmissionsP        | A “My requests” list                                | await wf.getMySubmissionsP(\{\})                            |
| getMySubmissionInstanceP | Opening one of my requests to see its status        | await wf.getMySubmissionInstanceP(instanceId)             |
| getWfInstanceP           | A progress tracker showing the steps of a workflow  | await wf.getWfInstanceP(instanceId)                       |
| getTaskActionsP          | Showing the right buttons (Approve, Reject)         | await wf.getTaskActionsP(taskid)                          |
| executeActionP           | Running the button click                            | await wf.executeActionP(taskid, "APPROVE", comment)       |
| getSubstituteActorsP     | Filling the “Reassign to” user picker               | await wf.getSubstituteActorsP(taskid)                     |
| substituteTaskP          | Delegating a task, such as when on leave            | await wf.substituteTaskP(taskid, newActor)                |

### **Example flow in a custom screen**

1.  gI(...) gets the service.

2.  getOpenTasksP shows the pending list.

3.  The user opens a task, and getTaskP plus getTaskActionsP load its details and buttons.

4.  The user clicks Approve, and executeActionP runs it.

5.  The user can instead delegate: getSubstituteActorsP, then substituteTaskP.

### **Good to know**

- Everything is limited to one flavor and to the calling user’s scope. Tasks outside that scope come back as “missing”.

- Reads work the same on client and server.
