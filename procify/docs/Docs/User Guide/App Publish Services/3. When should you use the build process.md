# When should you use the build process?

The build process is not needed every time; it should only be used in specific scenarios. Below are the cases when you should use the build:

1.  Under prodBuild, whenever the developer needs to deploy apps to the QA server, a build is required.

2.  After entity creation, whenever we change the persists on of the entity,build is required.

3.  Whenever we maintain the Parent -child hierarchy, we need to build.

4.  Whenever we are creating vh-config, we need to build.

5.  Before doing import/export of apps, you need to build.

6.  Whenever you create new version of app, we need to build (this build is done automatically by the account console)

7.  For mobile apps, whenever you want to test app changes, you need to build.

8.  For both devBuild and prodBuild, if we are creating new env roles then we need to build.

Note:

1.  When the fw_version of the application is changed, a new flavor_build must be created and re-registration will be required.

2.  The build process (both devBuild and prodBuild) should follow a parent → child order. You can trigger builds for both flavors at once. However, if the devBuild or prodBuild of a parent flavor has not been completed before building its child flavor, you will encounter an error like this:Error: **Parent app(s) parent_app must be dev/prodbuilt before building child_app**.
