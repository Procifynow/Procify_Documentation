# Workspace Hub — Create a new App

**Step 1:** Go to the **Apps** screen and click on the **Create App** button present at the top. It will automatically fill all data with random entries.  You can continue with it or you can change it.

**Step 2:** Change the app ID in the detail screen to the custom app ID of your choice or you can continue with the generated one. Add a name and description for your app.

Version(Major/Minor/Patch) represents the version on which the app will run. FW Version is the BOL version. 

**Step 3:** Choose the **Application Icon**.

Next, we will see [Flavor Alias, an auto-generated](https://docs.google.com/document/d/1cwusZmtaohyxZOGzlaq-_SeLGMtyQ3qEk3iLGCpAj-Y/edit) flavor name created at the transaction level while creating an app in the Workspace Hub. It should be unique for all apps. But for the branch level, it will be the same as the version. 

**Step 4:** Choose the Network Mode(default ONLINE). Network mode indicates whether the queries in the particular app should be fired online (directly to the server) or offline (to the web SQL in the browser).

**Step 5:** Choose whether the app will be supported in the device, browser or both from the App/Portal Support input (default BOTH).

**Step 6:** Provide the Remark or description for the app. This remark is reflected on the About Page where your app will be visible.

**Step 7:**  When you want to skip default app group creation( for Developer and Tester) then select the checkbox highlighted below during(new App/ Minor Version/Major Version) creation. 

**Note:**  choice selected will be considered while creating  patch versions of the same App.

**Step 8:** When you want to change your app version use the stepInput option to change version according to the need.

**Step 9: Select Auth Code (Default : COMMON)**

The Auth Code indicates a group of apps that manage the user/User Collections/app/App Collections for the particular app. It is a segregation process for users and apps.

Below there is a Publish Settings under which we have two options:

**Updates Code:** It will update the zip on the client side.

**App Data Update:** It will update the client-side table data, if any.

**Step 10: Save** the process. A new app will be created.

The publishing process will start. Once the app is published the new version will be formed and the old version will disappear from the app list. 

For creating FAQ keys for the app, go to FAQ Keys and you can either select the already created keys or you can create your own by clicking on the **Add** button.

**Step 10:** Click the **Save** button, and the app will be saved and start building, it will also pull the zip generated from the build. 

For a newly created app, a menu header is also added. 

**Important:** There are a few things we need to know about App Versioning. The App versions are written in 6-0-1(Major-Minor-Patch).

Here, 6 is referred to as Major

0 is referred to as Minor and,

1 is referred to as Patch

* When the patch is changed while versioning, the **roles & users** are automatically copied from the previous version to the recent version.  
* If the minor or major is changed then the **users** will not get copied from the previous version to the new version.  
* While creating a new version the patch number automatically changes, but when you want to create the app branch click on the branch button and it will create a branch with the latest version like major-minor+B-patch ,**Note:** When any new or hot fixes are made a new version should be created for that and an update should be taken for the same.

For more details follow this document on [App Branching & Merging -User Guide](https://docs.google.com/document/d/1ulu71U7-0T6iVrZqulKEvVacEo-DZBf_m2Rf3hFh-sU/edit)

## 9.1. Create a new Version {#9.1.-create-a-new-version}

**Step 1:**  Navigate to the app and then release the app following  the steps given below.

**Note**: If the app is a child app and the parent app version hasn't been released yet, you need to release those versions first.



**Step 2:**  Click on the **Version** button.

**Note**: When you click the version button, a patch version will be created by incrementing the patch number by ‘1’. To create a Major or Minor version, click the ‘+’ icon next to the respective version.

* 1-0-1 to 1-0-2: Patch version (this is the usual case when clicking the version button)  
* 1-0-1 to 1-1-0: Minor version (requires manually increasing the minor version using the step input)  
* 1-0-1 to 2-0-1: Major version (requires manually increasing the major version using the step input).

## 9.2. Create a Branch  {#9.2.-create-a-branch}

Step 1: If you want to create a **branch** for this application, first **release** the application. If it hasn't been **released**, click the **Branch** action button located at the top right side of the screen and **save**. The **"Is Branch"** option will automatically be enabled, and a branch will be added to the app list.

**NOTE:** Changes cannot be saved for released apps. A new active version must be created to make changes.

**Read more about:** [App Branching & Merging -User Guide](https://docs.google.com/document/d/1ulu71U7-0T6iVrZqulKEvVacEo-DZBf_m2Rf3hFh-sU/edit)

## 9.3. Recalculate AI Metadata  {#9.3.-recalculate-ai-metadata}

Recalculate AI Metadata is used to sync the application metadata changes to the AI server’s Database which will be accessed by the AI server for processing prompt requests.

**NOTE:** This button will be visible only if the landscape is Business AI or Embedded AI enabled and only if the selected application is Business AI or Embedded AI enabled.
