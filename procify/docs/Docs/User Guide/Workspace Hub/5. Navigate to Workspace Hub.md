# Workspace Hub — Navigate to Workspace Hub

Workspace Hub menu will be visible for Users who are assigned as **TESTER** or **DEVELOPER** or **SUPERADMIN.Step 1:** Go to the menu options and select **Workspace Hub.Step 2:** The Workspace Hub contains the following screens.



Under the menu header, **App Lifecycle**  users who are assigned as **TESTER** or  **DEVELOPER** or **SUPERADMIN**  wIll find **Auth Configuration** and **Custom Domains** menus.



 Under the menu header,App Lifecycle  users who are assigned  **SUPERADMIN**   and not as any application role wIll find the **App Authorisation**  menu.

First, we will look into the menus under the menu header **Workspace Hub**.

1. **AccountDetails \-** For overviewing the account details of the user and modifying it.   
* Account Name : **Account Name** are the basic details of the customer for which the account is created.  
* Account Type: **Account Type** are the basic details of the customer for which the account is created.  
* Valid Till: **Valid till** are the subscription period of the account which has been created for the customer.  
* Valid From: **Valid from** are the subscription period of the account which has been created for the customer.

2. **User Management \-** The User screen lists the users who are **filtered  based on logged in user’s Auth Configuration** whose accounts have been created under **current landscape**.We can check the details of the users, the User Collections one is assigned , the endpoints and apps assigned.

**Need help?:** Need help is the help and support section in an Workspace Hub that includes options for contacting customer support, such as phone numbers or email details, and links to important documents like Terms and Conditions, Privacy Policy, and Logo sections. You can also find details on sales inquiries or account management contacts.



3. **App Management \-** The Apps screen lists the Apps that are created in the current landscape for which logged in user has **MANAGER** access . Apps help create new apps, assign users based on roles to the app, and add language and FAQ Keys. use show External checkbox to show/hide external apps (default hide).

   Use ShowExternal to see external apps assigned to the user as manager.

   User ShowAll to see all the versions of apps assigned to the user as manager.



4. **User Collections \-** The User Group screen lists the User Collections who are  **filtered  based on logged in user’s Auth Configuration** and have been created under the **current landscape**.  A User Group is the section where a group of users using the same application are listed. User Collections are of two types :

   1\. Individual user group which is created by default for every user. By default individual User Collections are hidden, use show Individual checkbox if needed. Individual User Collections are needed to automatically assign newly created apps to the logged in user.

   2\. Group user group which was manually created.

   These groups of users can be assigned to  an app group. 

   

5. **App Collections \-** The App Group  screen lists the App Collections which are  **filtered  based on logged in user’s Auth Configuration** and have been created under the **current landscape**. The App Group is used to create groups that will consist of apps which fall under a particular project or that fall under a particular user. App Collections are of two types:

   1\. Individual App group which is created by default during every new , major and minor App creation. By default individual App Collections are hidden, use show Individual checkbox if needed. Individual App Collections are used to assign newly created apps to the logged in user.

   2\. Group App group which was manually created.

One can also add User Collections to the App Collections. 



6. **Login Sessions \-** Whenever any account is registered in the application, a new endpoint ID gets created against that account. It can be checked in the endpoint section. 



Now, we have three menus under the menu header **App Lifecycle.** Let us delve in to know what each does. 

7. **Auth Configuration \-** Here we will find the available Auth Configuration that are available in this tool and under this we can add or remove users according to our requirements.

   Auth Configuration are used to segregate users, apps , User Collections ,App Collections. It works as authorisation to particular users for apps, users, App Collections and User Collections.

    

8. **Custom Domains \-** [Custom Domains](https://docs.google.com/document/d/1CLIZ57ILYk-V4E0DR8ktny4R5yJ_yTKFDwuIDb8gMtk/edit#heading=h.414xfhnpeqvr) is a URL Development for redirecting a short url to its long url version. This process is done to make the URLs convenient for the end user's understanding. Short URLs improve the user experience by being easier to type out.  
9. **AI User Quota \-** AI User quota is a screen that will store the AI seat allocation details for the users. It consists of seat id clicking on which it will navigate to the AI conversation history screen. This screen is only visible to app admins.



10. **AI Conversation History \-** AI conversation history is a screen that has detailed information about the prompts and the corresponding responses that are given by user/’s using particular seats. This screen is only visible to app admins.





Now, we have a menu under the menu header App Lifecycle**.** Let us delve in to know what each does.

11. **App Authorisation \-** In this section, the accounts of the current or existing users will be shown and the users can assign or remove apps as and when required.
