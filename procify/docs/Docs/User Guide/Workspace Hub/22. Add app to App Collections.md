# Workspace Hub — Add app to App Collections

**Step 1:** Go to the **Apps** tab of the **App Collections** detail screen.

* **Step 2:** Click on the **Edit** button.

**Step 3:** Click on the **Add** button.

**Step 4:** A pop-up will appear. Select the apps and click on the **Add** button present at the bottom. Only apps having the same auth code as the app group and assigned as manager role to the logged in user can be added.

The app will be successfully added in the details section.

**Step 5:** You will have the option to specify:

1. **Update Type:** It specifies how the app will be installed. 

* **Regular:** It installs the registered app normally for the user and creates  initial sync, table generation, etc

* **On-Demand:** It helps to assign the app to the user but the user has to install the app through the Developer Page.

* **Default:** It is the same as regular installation type which helps the user to assign the app directly with table creation.

2.  **Upgrade Type:** It specifies how the app will be upgraded.

* **Immediate:** It upgrades the app with an immediate notification where the user will have the option of the **OK** button and it upgrades the app.

* **Postpondable:** It upgrades the app with an optional notification where the user will have the option of the **OK** and **Cancel** buttons and it will install the app later on.

3. **Role:** specifies via which role the application will be assigned to the users of that group.

4.  **Supported Channel**: It specifies that the application assigned to the user group will be for browser, device or both. You can toggle the buttons according to your needs.

**Step 6:** Click on the **Save** button.

**Note**: When displaying individual apps within App Collections:

* **Non-MANAGER roles**: Only the latest added version of an app is retained in the group. Older versions with the same major and minor version are removed upon new addition.

  * **MANAGER role**: All added versions of the app are retained, even if they share the same major and minor version.

This ensures that MANAGER roles can track version history, while non-MANAGER roles only reflect the latest active version.
