# Key mapping

Parent Key Mapping:

This is to auto populate the parent keys while creating an entity. Pass entity or JSON format on new entity creation. Keys are auto populated before save and accessible in UI controllers and callbacks. Key gets populated upto N level in a BO.

In case if the object type is not passed, it will return with error.

ID series gets generated on entity creation if applicable and populates the IDs to UI/Model. In case any child entity exists and ID is part of the primary key, it populates with the child entity also.

Mapping for already existing objects. Like two BPs are already created and map these as BP relations.

- **Primary relation:** If primary relation is maintained for two entities, keys get auto-populated from the parent. To understand this, take an example of order creation. While adding a line item in order, the order ID gets filled from the header automatically.

- **Aggregation:** This is to populate the key in the entity which is not part of the same BO. Separate metadata input required if key mapping to be supported in aggregation relation. Or API to be provided.

- **Association:** This is a structural relationship which connects one entity to another. An associate between two entities is able to navigate from one entity to another entity and vice versa.

Secondary key mapping: This is to decide either to perform create or update operation on messages received from Middleware.
