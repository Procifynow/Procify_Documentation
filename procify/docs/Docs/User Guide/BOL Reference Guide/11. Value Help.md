# Value Help

In Application, ID/key is frequently used to store the related data and at the same time in the user interface descriptive explanation is required. To achieve it, the ID/key is represented by other single/ multiple data from the related table. Value help is also used to supply the choices available to fill (combo, dropdown, auto complete) as selection data. Value help can impose the restriction for accepting the input value only from valid sets.

Value Help (VH) is an independent reusable object hence as a best practice always check the existing VHs for reuse before creating the new one. While creating a new one always categorises with entity names so later others can find it easily for reuse.

VH definition can be overridden in any used flavor. Except VHID and Entity Name(Group By), all parameters can be changed while overridden.

**Caching:**

VH values which are used by the user will get automatically cached on the browser. If the required value is not available in cache, the query gets fired to DB.

**Usage:**

- Provide users with a set of possible values or suggestion items in the UI.

- Get the suggestion list in callbacks.

- Show descriptive explanation in user interface.

**Steps for Value Help definition and usage:**

- Define the Value Help.

- Assign the Value Help.

- Maintain Suggestion List (If applicable).

## Types of Value Help

The type of ValueHelp needs to be selected while defining the ValueHelp in Data Studio depending on the scenario.**
**Following are ValueHelp Types:

- VH Query

- VH Saved Query

- VH Transaction

- VH Transaction Lang (VH Language Dependent)

- VH Config (Config)

- VH Config Lang (Config Language Dependent)

- VH System Field (Sys Fields)

### VH Query

For the VH type ‘Query’, Query ID to be provided as a parameter at the time of value help definition, which will return a set of values and be used as suggestion items. It could any type of Query :

- Runtime Query : Root Entity or queries associated with the root entity.

- Modelled Query : Query ID.

- Native Query : Query ID

Entity authorization is automatically applied on the queries assigned to VH.

- Select the VH type as **‘Query’**.

- Select any existing **Query ID or Entity Name**.

- Key, Value and Dependent fields are enabled and these attribute’s values can vary based on the query type selected.

Key Property & Display Text:

- If a Runtime Query is selected it contains the **entity properties** from the **selected Entity Name**.

- If a Modelled query or Native Query is selected it contains the list of **entity properties** of the **return Entity **of the **selected Query.**

**Dependents :**

- If Runtime Query is selected it contains a list of **entity properties** from the **selected Entity** represented as **EntityName.PropertyId**.

- If the Modelled query or Native query is selected it contains a list of **query properties** based on the selected query.

**Icon:**

- Entity property of return entity where SAPUI5 icon URL or image path is stored.

Maintain the data in the return entity of the selected query. Depending on the scenario data maintenance needs to be taken care of by application.

- Master data

- Transactional data

**Example:**
Let’s assume the valueHelp is grouped under *“d_material“* Entity which has *material_id* and *material_description* as two properties.

The **Key** is set to *material_id* and **Display Text** is set to *material_description.*

Both Key and Display Text values can be displayed to the user concurrently or just Display Text can be shown and the key is set internally.

**Dependent Example :**

Let's assume there are two comboBoxes/AutoComplete which contain Country, State.

- In the query, create one query properties **country** and create the query as

> SELECT ***id, state_name FROM d_states WHERE country =:country***

- And assign the query property ‘*country’* as a dependent field.

- Take the country from the first comboBox and fire the Query which gets required Data.

- Multiple Dependent Properties are Not supported.

> If Multiple Dependent Properties are required, fire a Query with multiple query properties(where conditions) and assign the model explicitly.

- Refresh Dependent VH: when parent field value changes, the dependent VH gets refreshed.

### Saved Query

Saved Query VH is similar to Query VH type with predefined possible inputs, these saved queries can be used in ValueHelp as well. Each savedquery is associated with one of the queries i.e Runtime, Modelled and Native queries so these also work similar to QUERY.

- Select the VH type as ‘Saved Query’.

- Select any existing **saved query id**.

- key, Value and Dependent fields are enabled and work the same as Query type.

### VH Transaction

VH Transaction is a common ValueHelp functionality provided by KloBase which can fulfil most of the basic requirements in application. Here you can maintain the suggestion values for multiple ValueHelps. This is part of the transaction database. Which is also synced in the device at the time of initial sync and values are fetched from the same. No need to create any query.

Define VH Transaction:

- Enter VHID

- Select VH Type as **‘VH Transaction’**

- Parameter: parameter is defaulted with VHID but the developer can change this and provide any Category name.

- Key, Value, and Dependent attributes need not to be filled. By default consider vh_transaction entity properties.

**Data maintenance:**

| DependentFilter     | Maintain the dependent filter value based on which suggestion item list gets filtered.Example: In case of State and District VH, maintain State value as a dependent filter.                                                                                                         |

### VH Transaction Language

This is similar to **VH Transaction** type, the only additional filter considered here is **language**. KloBase provides an option to capture value help id, filter, description, icon, language code and translated description. Start creating a valuehelp by selecting the object type as ‘VH Transaction Lang’ and in the ***parameter*** field, provide the category in which the value should get filtered from the table

- Same ‘Key’ in VH Transactions can have multiple values with diff languages.

- When this type is identified, the values are filtered based on the given parameter at the time of VH definition and Language.

- Lang is taken from the browser default language.

- If the values are not present for a given language, the KloBase returns default system lang values.

> **Example:** Out of 5 values for a VH only 3 are maintained in diff languages and 2 values are maintained only in system default lang, in this case it will return 5 values(3 with browser lang and 2 with system default lang)

- Language priority: User setting \>\> Account \>\> Browser

### VH Config

### System Fields

Every Entity is associated with system properties like *s_object_type, s_object_group, s_status, s_status_custom* each of these are in turn associated with their own description, icon etc.
Hence these system fields can be used as valuehelps. This will be primarily useful in the callback to get the list of suggestion values or display text in the UI. The values for these are stored as metadata.

**Example:**

| **s_object_type** | **Entity name** | **Description** |
|-------------------|-----------------|-----------------|
| 101               | d_so_hdr        | Regular Order   |
| 102               | d_so_hdr        | Express Order   |

- System fields like s_object_type, s_object_group, s_status can have their own description and icon provided as a part of definition.

## Assign Value Help

Once VH definition is in place, this can be assigned to any PropertyType (Property type captures the value help id used for the entity property).

This is a reusable unit and can be assigned to multiple PropertyTypes.

- VH assignment can be overridden in PropertyType in any flavor along with owning flavor.

- Can remove value help assignment in any used flavor by Changing/Creating PropertyType or Change UI field to **“Input”**.

## Value Help APIs

When an entity property has value help (property type holds a value help id), then a new property with name **\[\<property_name\>\_vh\]** is available. **\[\<property_name\>\_vh\]** returns a ValueHelp object.

- Value Help Properties:

  - *dependentFilter:* to set the filter value.

  - *suggestionItemsFilter:* set value for live change.

  - *description* : returns description string.

  - *suggetionItems* : returns EntitySet containing the Entities as suggestions.

  - *selectedItem* : returns the EntitySet containing the selected item as Entity.

  - *additional_desc*: Returns the value of the resulting entity’s properties in the given format.

  - *icon* : returns the string icon value provided.

- These properties are bindable to UI controls and can be used in Rules.

- While using, make sure it is loaded completely, since this can go for a lazy load.

For detailed Value Help APIs refer to [*BOL ValueHelp API*](https://docs.google.com/document/u/0/d/1wNTiZPl7YfjzmGjNdIuRv5YGjT0zsY8iJYI_ObuyBy8/edit).

## UI Control

Pre-defined UI control is provided from Framework which takes care of everything including API calls. This control extends the UI5 controls.

Custom Controls:

- InputExtender

- ComboBoxExtender

InputExtender:

- InputExtender extends Input control.

- Use for a bigger list.

- It is mandatory to provide VHID.

- Key and Value property: key is binded to model and get stored to DB. Value is to show in UI and binded to the ‘description’ in VH.

- In case of dependent VH, provide dependent property and its type.
