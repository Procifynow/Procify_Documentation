# kloIDSeries

ID series are used for populating the IDs/ Key in the entity’s property by kloBO. If an application wants to allocate the ID itself, either it should not assign the ID series or mark it as none. kloBO will allocate the ID on the first read of the ID.

### How to assign the ID series to Entity Property

ID Series are customizable in application during configuration hence it supports override or selection of id series based on Brand and Object Type. Applications can maintain multiple entries of ID Series (Entity, Property, \[Object Type\], \[Brand\] —\> ID Series). Most accurate matching ID Series definition is picked by kloBase for further processing based on precedence first to object type next to brand.
For example, the **Order** Object has maintained the following:

- ID series “order_base_series” with no Brand and no Object type

- ID series “order_b1_series” with “B1” Brand and no Object type

- ID series “order_ot1_series” with no Brand and no “1” Object type

- ID series “order_b1_ot1_series” with “B1” Brand and “1” Object type

Object type abbreviation? \$objecttype.abr

If the order instance in question belongs to B1 and object type 1 then order_b1_ot1_series definition will be picked for processing.
If the order instance in question belongs to B1 and object type 2 then order_b1_series definition will be picked for processing.
If the order instance in question belongs to B2 and object type 3 then order_base_series definition will be picked for processing.

### Precedence Rule

- Highest: Exact match of ObjectType and brand.

- Medium: Exact match of Object type and Brand as “All”.

- Low: Object type “All” and Brand as “All”.

- Lowest: no key allocated.

### ID Series Types

ID series support two types of counters.

- GUID: returns 32 char UUID as key.

- Autonumber: returns incremental number for allocated chunk. The auto number section.

- None: no number is assigned to the developer to fill the number. Generally used during override in tuner to remove the ID series.

ID series value to be filled in the assigned entity property comes from the counter. Once the counter generates the key it can be formatted with prefix, post fix, \$vars etc.

Counter and pattern to be filled.

### AutoNumber

AutoNumber is a running number that starts from the start till the end. Each tenant and offline devices get the reserve interval from the auto number. Size of the allocated interval can be controlled using the size parameter.

Scope:

Default is global, only one autoNumber is used for all the tenant and offline endpoints interval.
Tenant: per tenant separate series is used.
User: per user separate series is used.
Chunksize: default 100 can be set to desired number.
Range: start and end range.
