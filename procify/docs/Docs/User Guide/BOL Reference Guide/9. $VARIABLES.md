# $VARIABLES

Set of frequently used values, which remains constant, are provided as variables. These are framework provided and are **extensible in shared flavor**. But can not alter the framework provided fields.

**\$USER**

- login_id,

- employee_id, (userID)

- Owning_bp

- ExtendedBP

- \+ application extended fields.

&nbsp;

- USER data is synced as a part of initial sync. All updates on user data are communicated to relevant endpoints of the user by FW vai kloBrokermessage using a user entity. Client side user entity should update the global \$user variable.

**\$BP** has

- me,

- bp_type,

- Has_own_tenant

- \+ application extended fields

**\$ROLE**

\$role is a configuration data that needs to be modified only on dev and deployed on QA,PROD. It does not depend on flavor/version. And available for extension in Shared flavor.

- Application maintained data in the extended fields. Useful for controlling the UI Controls visibility/ editability per role within the flavor.

- My Role date is synced as a part of initial sync. All updates on the role date are communicated to relevant users by FW vai kloBroker message. On assignment of a new app to a user this is also pushed to the user.

**\$SYSTEM** (readOnly) - non extendable by application.

- **flavor** --transient field and calculated in runtime and set

- **version** --transient field and calculated in runtime and set

- **role** - not Available as kloBroker

- **userID** - not Available as kloBroker

- **isMiddleWare**

- **isScheduler**

- **today** --transient field and calculated in runtime and set (date )

- **now** --transient field and calculated in runtime and set (timestamp value)

**\$GLOBAL**

Application defined fields act as global variables.

Gives the substitute feature.

**Usage**

All the above global variables are accessible on the event object, \$Global is only available in client.

When used as a string literal in a meta model in query, id series, authorization it is replaced with real value. E.g. **\$USER.login_id** will be replaced with the currently logged in user id.

Syntax: \$\{\<Variable name\>.\<property id\>\}

**API**

EnvironmentalVariable.getEnvironmentMap(flavor,version) will return the env variable map, which will have all the ENV objects as key- value pairs, and use the ENV variable name to get the actual Variable Entity.

BaseController has API to access ENV Variables in Controllers, Please refer KloTouch API

event\[‘\$USER’\].login_id; will return you the current logged in user id;
