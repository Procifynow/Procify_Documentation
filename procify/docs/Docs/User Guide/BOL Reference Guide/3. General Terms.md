# General Terms

## Domain

A domain is a unique set of values permitted for an attribute in a table. KloBase Datastore supports a variety of data types for *property* values. A domain represents data type.

The following domain types are supported :

| I16             | number        | Number(5,0)  | number                | number                |

## NetworkMode

A **network mode** is a state, or means of operating, that a wireless network can employ. In other words, they describe the various operational characteristics of the wireless signals. kloBase supports a rich set of network modes. The two most frequent network modes are **online** and **offline**.

**Online:**

- Online network mode refers to the capability of running the program in a browser or installed mobile app (client) to communicate with the server for day-to-day needs.

- Network connectivity from client to server is a must. For example, if the screen needs to show Open Orders, kloBO will go to the server to get the data for Open Order and give it to the UI for display.

- All the changes on the browser or device app will be collected and sent to the server for validating and saving.

**Offline:**

- Offline network mode refers to the capability to run the program with weak or infrequent network availability.

- The application stores the relevant data locally and keeps the local cache and server data updated as and when it finds connectivity.

- Browsers and installed mobile apps (client) both are capable of offline operations.

**Cached Online:**

- It refers to the client’s capability to connect with the server whenever required.

- Speeds up the interaction of the client with the server by suggesting data from the local cache.

**Offline Confirmed:**

- It refers to the capability of the client to serve data offline.

- The save (message) always goes through online.

- It modifies the local cache.

- There is no message flow from offline to server during modification.

**SAP Online:**

This refers to the capability of all the transactions that go to SAP via the gateway server.

**SAP Cached Online:**

Refers to the configuration of the web browser or mobile application in such a way that the contents (static and dynamic) are stored in the cache, and the next request to the page concerned can be satisfied quickly from the cache.

## Client

The medium through which the end users log into the application is known as the client. Web browsers are used to open an online application, here the browser is the client. Similarly, when an Android application is installed on mobile to run an application, the Android app becomes the client. Each client is identified by a unique identifier called the endpoint ID.

## Tenant

Tenant is an environment or space created for the users' data storage. Physical data on a server needs to be partitioned across multiple sets of users. Generally, in any multinational organisation, each department owns a tenant. Each tenant is assigned a unique endpoint ID. Individual tenants can host data for multiple organisations.

## End Point

Endpoint helps klobroker in sending and receiving messages across various participants. Each endpoint is identified by a unique endpoint ID. Every user logging into an application sends a signal to the server through the installed app. Hence, each installation gets a unique endpoint ID. Each browser gets an endpoint ID. Every individual tenant and the external system linked to the server have an endpoint ID.

## Channel

When one endpoint (source) sends the instruction (message) to another endpoint. The receiving endpoint (target) gets the message through the channel.

## LoadAll

The **loadAll** feature retrieves all available rows from the database, including all configured properties for each record, in a single query execution.

To enable this feature, set the loadAll flag on the queryInstance object before executing the query:

queryInstance.**setLoadAll(true);**

To revert to the default behavior, disable the feature and then execute the query:

queryInstance.**setLoadAll(false);**

**Note:** Enabling loadAll may increase memory consumption and query execution time when working with large datasets, as all records and properties are fetched at once.
