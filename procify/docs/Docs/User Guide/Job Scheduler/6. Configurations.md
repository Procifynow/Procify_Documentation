# Configurations

## Code

- Create a folder named: ‘scheduler’ inside the App.

- Inside the scheduler flavor, scheduler files can be created with the same name as **‘scheduler_id’**.

- Inside the files, the class name should be **‘scheduler_id’** and should extend the kloBo/kloScheduler/KloScheduler class.

- Developers must override the onExecute method of the parent class, which gets executed on a defined time.

- eventContext and params can be accessed through **‘this’** keyword.
  > E.g: this.eventContext, this.params .

- The flavor build needs to be triggered after the creation/modification of the file.

- If the **onExecute()** function is not found on the scheduler file,it will execute the function from the parent class and the Jobs will be returned with **COMPLETED** status.

- If we want the Jobs status to be failed,we can call the **throw(“string”)** function in the **onExecute()** Function of the scheduler file.The String passed to the function will be displayed in the log.

## Job Priority

Background jobs are classified into four categories: -

- **Class S (System):** A class system for fw jobs. System jobs are not part of the quota

- **Class A (Critical Priority)**: - Some tasks are urgent or critical and must be scheduled with class A priority jobs. Class A priority reserves one or more background work processes. Users must decide how many background work processes should be assigned to Class A priority jobs.

- **Class B(Normal Priority)**: - Once Class A jobs are completed, Class B jobs will start executing in the background before Class C jobs.

- **Class C(Low Priority)**: -It runs after class A and class B jobs are completed.
