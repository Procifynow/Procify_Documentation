addEndpoint

  • addEndpoint(endpoint, type, channel, object, onlydirtyobject?, onlyRootEntity?): EndPointBean

  • Parameters

    NameTypeDefaultDescription
    endpointstring | string[]

    endpoint id or array of endpoint ids to which the data message has to be sent. Based on the type of endpoint the id will be if type is BP_USER then endpoint has to be BP_ID. The data message will be sent to all the endpoints active of user's in the BP. if type is ENDPOINT then endpoint has to be ENDPOINT_ID. The data message will be sent to the endpoint, it can be a device or it can be an external system. if type is USER then endpoint has to be USER_ID. The data message will be send to all the endpoints active of the user.

    typeEndpointType

    based on the type endpoint will be processed.

    channelChannelType

    filter to restrict the endpoint-ids qualify to this channel type only. The final result of endpoints will be filters based on the channel type. If not provided the default is DEVICE

    objectKloEntity

    This object specifies which object's data has to be sent to the endpoint. The message will be generated for the whole object's BO tree. All the child entities which are dirty will be sent.

    onlydirtyobjectbooleantrue

    When sending the data message, by default only the dirty child entity objects will be sent. But if all the child entity objects irrespective of their dirty state has to be sent, set the parameter to false. This will trigger all the child entity objects irrespective of their dirty state.

    onlyRootEntitybooleanfalse@@@

    Returns EndPointBean

    EndpointBean containing all the details regarding the message.

    Description

    addEndpoint API is used to trigger data messages to endpoints. Adding an endpoint will send a the data message to the endpoint. This can be used to sync endpoints (explained below) to updated data. This will trigger message a specific audience or huge number of endpoints.

    See

    addEndpoint for adding endpoint in event context.

    Example

    txn.addEndpoint("BP001", EndpointType.BP_USER, ChannelType.DEVICE,myBO);
    The above example will trigger a myBO data message to all the devices (ChannelType.DEVICE) of the users assigned to BP001 (EndpointType.BP_USER).

    txn.addEndpoint("BP001", EndpointType.BP_USER, ChannelType.DEVICE,myBO, false);
    This example is same as the above one, but this will trigger message will all the dirty and non dirty child entities of myBO.

addNotification

  • addNotification(template, entObject, userObject?, to_list?, cc_list?, ref_id?, params?): NotificationBean

  • addNotification is an API which can be used to trigger notification to the users. This can be used to trigger SMS, EMAIL and push notification for a given set of users with a specific template. addNotification should only be called on the server environment. This API will trigger a notification, it will be add notification to queue, it will picked and processed based on the queue. So, use addNotification for triggering notifications which are not immediately required. Eg. Status update, Report generated notification,...

    Do not use for:

    1. Triggering time critical notification which has to be sent immediately. Notification triggered with this API will be added to queue and will be processed later based on queue / service availability. For triggering the notification immediately, use sendInstantNotification

    Parameters

    NameTypeAttributesDescription
    templatestring

    notification template id should be provided for template. Notification template can be crated using {elink notification editor documentation}.

    entObjectKloEntity

    Object is a entity object from which data can be used to replace the template variables.

    userObjectany<Optional>

    UserObject can be used to provide custom properties to the template which are not provided from the object. The same properties from entObject will be overridden by the userObject.

    to_liststring[]<Optional>

    to_list is an array of string (user_id / mobile number / email id) to which the notification has to be sent. If none is provided the current env user will be taken. Email, mobile, and Endpoints of the user will be used from the user details with user_id. If email is disabled or template not present, all email ids in the list will be ignored. If SMS is disabled or template not present, all mobile numbers in the list will be ignored. mobile number / email address / Push notification endpoint is pulled from user id. If App is enabled, all the endpoints will get the push notification.

    cc_liststring[]<Optional>

    cc_list is only used for email.

    ref_idstring<Optional>

    ref_id can be used to keep a reference of the spool table entries

    paramsPARAMS_FOR_NOTIF<Optional>@@@

    Returns NotificationBean

    NotificationBean containing all the information regarding the triggered notification. The returned notification bean can further be customized before committing the transaction using NotificationBean APIs.

    See

    • sendInstantNotification for sending instant notifications
    • addNotification for the same API via event object.

    Example

    txn.addNotification("reportComplete", null, {reportid: "Age Report"}, ["user101", "user104"], ["user002"]);
    The example shows a notification triggered for template reportGenStatusUpdate
    Notification template: for EMAIL type.
    Report : <%=reportid%> is generated.

    The reportid from the userObject will be substituted and EMAIL will be sent with
    Report : Age Report is generated.
    TO: user101@email.com, user104@email.com
    CC: user02@email.com

createEntityP

  • createEntityP(entityName, entityJson?, deepClone?, mappingRule?): Promise<KloEntity>

  • Parameters

    NameTypeAttributesDescription
    entityNamestring

    name of the entity for which the new object has to be created.

    entityJsonany<Optional>

    valid JSON Representation of Entity or Entity object itself. Object representation can be partial. When JSON / Entity is provided, the property value is looked up, if the property exists, it is copied. Primary key with ID series is ignored. If a non root entity is created, primary keys of parent entity should be provided in the JSON itself. If object belonging to different entity is provided, copying one property with another property can be achieved with mappingRule parameter. All the fields marked internal ID series are populated. All the fields with default values are populated with default values.

    deepCloneboolean<Optional>

    whether to copy the relation data of the entity recursively. Entity can have relation to other entities who can have relation with more entities and so on. Thus, when a KloEntity object is provided as entityJson param, it will recursively load all the relations and create in the new entity object. JSON as entityJSON is also supported with deepClone as long as the properties and relations are properly provided.

    mappingRuleMappingRules<Optional>

    mappingRule is an optional property which can be used for mapping property and relations of a different JSON or entity object. check MappingRules for more information on mapping rules.

    Returns Promise<KloEntity>

    newly created entity object

    Description

    This method creates a new entity object for the specified entity name, and returns the newly created entity object KloEntity. Users can specify the properties data while creating the object. If it is a new child entity it is mandatory to supply the parent entity primary keys. onAfterCreate method of the will be called at the end of newEntityP function execution.

    See

    • upsertEntityP for updating if data is already present or create if not.
    • newEntityP for creating entity with KloEntitySet API.

    Throws

    KloError instance.

    Example

    let ent_1 = await txn.createEntityP("d_no_hdr"); // newly entity object is created for d_no_hdr entity.
    ent_1.short_text = "CreateEntityP API demo";

    let ent_2 = await txn.createEntityP("d_no_hdr", {
     short_text: "CreateEntityP API demo",
     description:"This object is created for transaction.createEntityP API demo."
    }); // short_text and description is provided in the entityJson object.

    let ent_3 = await txn.createEntityP("d_no_hdr", {
     short_text: "CreateEntityP API demo",
     description:"This object is created for transaction.createEntityP API demo.",
     item: [
         {"itemid": 1, "count": 45},
         {"itemid": 1, "count": 45, reason: "Item is used for some purpose."}
     ]
    }, true ) // deep clone is provided as true, this will copy the value for entity object of d_no_hdr and also creates entity in item relation with values provided.
    // 2nd parameter entityJson can be both JSON object and entity object.

    let ent_4 = await txn.createEntityP("d_no_work_order", {
     short_description: "CreateEntityP API demo",
     description:"This object is created for transaction.createEntityP API demo.",
     orders: [
         {"itemid": 1, "nos": 45},
         {"itemid": 1, "nos": 45, reason: "Item is used for some purpose."}
         ]
     },
     true, // deep clone
     [ // mapping rule
         "short_description:short_text", // short_description will be copied form short_text
         "item:orders",
         "item/count:orders/nos"
     ]);

createTransaction

  • createTransaction(flavor?): Promise<KloTransaction>

  • Parameters

    NameTypeAttributesDescription
    flavorstring<Optional>

    Optional flavor name for creating a transaction in a different application module. If not provided, uses the current transaction's flavor. Avoid using this parameter unless necessary.

    Returns Promise<KloTransaction>

    Promise that resolves to a new KloTransaction instance

    Description

    Creates a new transaction instance with the same environment context as the current transaction. The new transaction will inherit the environment variables from the current transaction but will have a fresh persistence context. This is useful for operations that need to be isolated from the main transaction.

    Example

    // Create a transaction in the same flavor
    let newTxn = await txn.createTransaction();
    let query = await newTxn.getQueryP("d_order");

    // Create a transaction in a different flavor
    let eamTxn = await txn.createTransaction("eam");
    let eamEntity = await eamTxn.createEntityP("d_asset");

    See

    createTransaction for static transaction creation

    upsertEntityByUniqueKeyP

    • upsertEntityByUniqueKeyP(entityname, entityJson, deepClone?, mappingRule?): Promise<KloEntity>

    • Parameters

      NameTypeAttributesDescription
      entitynamestring

      name of the entity for which the new object has to be created / updated.

      entityJsonany

      valid JSON Representation of Entity or Entity object itself. Object representation can be partial but should contain all the primary fields and unique fields mandatorily. When JSON / Entity is provided, the property value is looked up, if the property exists, it is copied. Primary key with ID series is ignored. If a non root entity is created, primary keys of parent entity should be provided in the JSON itself. If object belonging to different entity is provided, copying one property with another property can be achieved with mappingRule parameter. All the fields marked internal ID series are populated. All the fields with default values are populated with default values.

      deepCloneboolean<Optional>

      whether to copy the relation data of the entity recursively. Entity can have relation to other entities who can have relation with more entities and so on. Thus, when a KloEntity object is provided as entityJson param, it will recursively load all the relations and create in the new entity object. JSON as entityJSON is also supported with deepClone as long as the properties and relations are properly provided.

      mappingRulestring[]<Optional>

      mappingRule is an optional property which can be used for mapping property and relations of a different JSON or entity object. check MappingRules for more information on mapping rules. mappingRule will only be applicable if it is create condition, not update condition.

      Returns Promise<KloEntity>

      newly created / existing updated entity object

      Description

      This method creates a new entity object if not already present. If data is present with same unique fields, it will update the other fields. and returns the newly created / updated entity object KloEntity. If there are duplicate data in DB for the key it will throw duplicate data error. Users can specify the properties data while creating / updating the object. Similarly, All cases for the createEntityP will be applicable for this method. Note, upsert is expensive method as the data is pulled from database to confirm whether the entity object exists with the unique key. Thus, only use upsertEntityP if you want to update if already present and not create all the time.

      See

      • upsertEntityByUniqueKeyP for using the same method in KloEntitySet instance.
      • createEntityP for creating entity instead of upsert.

      Throws

      KloError instance.

      Example

      let ent_1 = await txn.upsertEntityByUniqueKeyP("d_no_hdr"); // newly entity object is created for d_no_hdr entity.
      ent_1.short_text = "upsertEntityByUniqueKeyP API demo";

      let ent_2 = await txn.upsertEntityByUniqueKeyP("d_no_hdr", {
       short_text: "upsertEntityByUniqueKeyP API demo",
       description:"This object is created for transaction.upsertEntityByUniqueKeyP API demo."
      }); // short_text and description is provided in the entityJson object.

      let ent_3 = await txn.upsertEntityByUniqueKeyP("d_no_hdr", {
       short_text: "upsertEntityByUniqueKeyP API demo",
       description:"This object is created for transaction.upsertEntityByUniqueKeyP API demo.",
       item: [
           {"itemid": 1, "count": 45},
           {"itemid": 1, "count": 45, reason: "Item is used for some purpose."}
       ]
      }, true ) // deep clone is provided as true, this will copy the value for entity object of d_no_hdr and also creates entity in item relation with values provided.
      // 2nd parameter entityJson can be both JSON object and entity object.

      let ent_4 = await txn.upsertEntityByUniqueKeyP("d_no_work_order", {
       short_description: "upsertEntityByUniqueKeyP API demo",
       description:"This object is created for transaction.upsertEntityByUniqueKeyP API demo.",
       orders: [
           {"itemid": 1, "nos": 45},
           {"itemid": 1, "nos": 45, reason: "Item is used for some purpose."}
           ]
       },
       true, // deep clone
       [ // mapping rule
           "short_description:short_text", // short_description will be copied form short_text
           "item:orders",
           "item/count:orders/nos"
       ]);

    waitForAttachmentUploadsP

    • waitForAttachmentUploadsP(): Promise<"COMPLETED">

    • Returns Promise<"COMPLETED">

      Returns "COMPLETED" when all attachments are uploaded

      Description

      Waits indefinitely for all attachment uploads associated with entities in this transaction to complete. This method polls the attachment upload status every 500ms until all attachments finish uploading. The internal status variable is updated throughout the polling process. Non-attachment related errors are thrown immediately.

      Since

      fw_version 7.2

      Throws

      If non-attachment related errors occur during validation

      Example

      // Wait indefinitely for attachments to complete before saving
      await txn.waitForAttachmentUploadsP();
      await txn.commitP();

      Example

      // With error handling for non-attachment errors
      try {
          await txn.waitForAttachmentUploadsP();
          await txn.commitP();
          sap.m.MessageToast.show("Saved successfully with all attachments");
      } catch (error) {
          // This will only catch non-attachment related errors
          sap.m.MessageBox.error("Failed to save: " + error.message);
      }
