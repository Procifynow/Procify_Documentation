LoadEntityByKeyP

  • LoadEntityByKeyP(key, onlyCache?, forceExe?): Promise<KloEntity>

  • LoadEntityByKeyP is used to load the complete entity object by its unique key. The unique key of the entity is constructed using the entity name and primary key set. For example: Consider an entity of name d_order and primary key set as order_id and plant_id. for a entity object with data {order_id: 1, plant_id: 2}, the unique key is constructed as d_order@@1@@2 {entity_name@@primary_field_value1@@primary_field_value2@@...} with primary keys in alphabetical order. Get unique key of the entity using KloEntity#getEntityUniqueKey(). Note: This method will check if data is in cache, if not it will fetch from server. Thus for loading a large number of entities, it is recommended to use executeP with appropriate filter.

    Parameters

    NameTypeDefaultAttributesDescription
    keystring

    key is constructed like explained above.

    onlyCachebooleanfalse

    If onlyCache is true, it will only look for the entity in the already loaded cache.

    forceExeboolean<Optional>

    If forceExe parameter is marked as true to skip caching and get data directly from DB

    Returns Promise<KloEntity>

    Promise resolving into Entity Object. If Entity object for given key is not found, will return null.

    See

    KloEntity#getEntityUniqueKey

    Example

    /*
    consider an entity d_order with primary key set as order_id and plant_id.
    when you want to load an entity object with order_id as ORD001 and plant_id as PL001, the unique key is constructed as d_order@@ORD001@@PL001
    */
    let entity = await queryInstance.LoadEntityByKeyP("d_order@@ORD001@@PL001");
    entity.order_id; // ORD001
    entity.plant_id; // PL001
    entity.responsible; // will return the value of responsible property of the entity.

executeP

  • executeP(): Promise<KloEntitySet<KloEntity>>

  • Returns Promise<KloEntitySet<KloEntity>>

    Query result set.

    Description

    executeP will go for execution of query to fetch the result. The Query is prepared by setting all the required properties and parameters. ExecuteP returns promise. Once execution completes, the promise is resolved with the kloEntitySet which represents an array of entities as a result. On the same Query if executeP is called more than once, re execution will happen only if forceExecute is true or query input has been changed from last execution. Earlier executions if in process are rejected with “Cancelled” error. When re execution is ignored, the old execution promise is returned. queryInstance.executeP always returns the same instance of kloEntitySet which can be directly retrieved from query.entitySet executeP only fills it with appropriate results. Network mode and KloTransaction can’t be changed in subsequent execute calls. If any property is set “null” it will get ignored at the time of query execution. Note:

    1. If loadAll is not explicitly set to false, it will default the loadAll property to true.
    2. For large datasets (>10K rows), consider using executeStreamP() to prevent memory issues. executeStreamP() returns data in chunks and prevents Node.js from running out of memory.

    See

    executeStreamP For memory-efficient streaming execution of large datasets

    Example

    let q = await transaction.getQueryP('d_no_hdr');
    q.setLoadAll(true);
    let es = await q.executeP()

    Example

    // For large datasets, use streaming:
    let stream = await q.executeStreamP(1000); // 1000 rows per chunk
    while(!stream.isLast) {
      // Process stream (KloEntitySet with entities)
      stream = await q.getNextChunk();
    }

executeStreamP

  • executeStreamP(rowsPerChunk?): Promise<KloEntitySet<KloEntity>>

  • Parameters

    NameTypeAttributesDescription
    rowsPerChunknumber<Optional>

    Optional number of rows per chunk. If not provided, uses default chunk size.

    Returns Promise<KloEntitySet<KloEntity>>

    Promise that resolves to the query's KloEntitySet containing current chunk with isLast and requestId properties.

    Description

    executeStreamP executes the query and returns a KloEntitySet with the first chunk of data. The query's entityset (accessible via query.entityset) will contain the current chunk's entities. Each call to getNextChunk() will replace the contents of query.entityset with the next chunk. The entityset contains isLast and requestId properties for streaming control.

    IDEMPOTENT: Calling executeStreamP() multiple times while a stream is active will return the same first chunk. This allows safe retries without creating duplicate streams. To reset and start a new stream, call closeStream() first.

    Example

    let stream = await q.executeStreamP(100);

    // Can access via return value OR query.entityset
    console.log(stream.length); // 100
    console.log(q.entityset.length); // 100 (same)
    console.log(stream === q.entityset); // true

    while(!stream.isLast) {
      stream = await q.getNextChunk();
      console.log(q.entityset.length); // Updated with next chunk
    }
    await q.closeStream();

refreshP

  • refreshP(deepRefresh, forceState?): Promise<KloEntitySet<KloEntity>>

  • Parameters

    NameTypeDefaultDescription
    deepRefreshboolean | entityRefreshConfig

    boolean value for deep refresh or customized refresh for the relations.

    forceStatebooleanfalse

    forceState is used with deep true, if true refreshes the relations even if no entity in the entity set is dirty. default is false

    Returns Promise<KloEntitySet<KloEntity>>

    the result entity set

    Description

    Discard all the unsaved modification including new entity and deleted entity and restores the state back as it was before the dirty state. This is equivalent to calling refresh on all the entities participating in entityset. Post discard newly created entities will vanish from entity set, deleted will reappear at the top and modified will start showing old values. The filters state (not query properties) is not considered in Refresh, all the entities, which are not visible because of filters, also get refreshed. Deleted objects will appear back on the top in entitySet again even if it is disqualified by filter. The sequence of entities in entityset may change after refresh. The Pagination state of individual entities are retained as is during refresh. If expandAll is applied on a query then all the expanded relations also get refreshed. Entity set will be matched back with DB for newly added, removed entities coming to DB via other channels, transactions like MW sync, delta sync etc. deepRefresh : boolean = false | true Above description covers the behavior of false. Default value is false. For deepRefresh = true value. All the loaded relations ( primary, aggregated and others) are discarded except expandAll relations. With pagination disabled (loadAll = true) all the data will be reloaded for the entities of this entity set from dB. And in case of pagination data will be discarded. Behavior remains the same for offline, online and preferred online.

    See

    executeP for executing the query with retaining the dirty state.

    Example

    let result = await queryInstance.executeP();
    console.log(result[0].text); // prints "Original text"

    await queryInstance.refreshP();
    console.log(result[0].text); // prints "Original text"

This method is used to skip loading data from cache and load from server only. Setting this property will only change the query condition, to take get result executeP must be called.

    • getSkipMap for getting the current value of skipMap
    • skipMap for getter and setter version of this function

    Example

    // consider a query instance of entity d_order with primary key order_id and another regular field as short_text.

    console.log(result[0].short_text); // prints "short text before some else modified and committed".

    // consider someone else modified the short_text property of the same entity and committed as "short text after someone changed it".
    // now if you execute the same query again, it will load the data from cache and will not load from server.
    result = await queryInstance.executeP();

    Use skipMap only when needed: for comparing data or checking for duplicates.
    It may impact performance in case of large data sets.
