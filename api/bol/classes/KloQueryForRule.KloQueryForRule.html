getResults

  • getResults(): Promise<any[]>

  • Returns Promise<any[]>

    raw query result as an array of JSON object representing entity objects.

    Description

    returns the raw query result as an array of JSON object representing entity objects. These objects are not of type KloEntity and can not be used for performing create, update or delete operations. This can be used to get the result of query in after query callbacks. Similar to getResults

    See

    setResults for setting the raw query result and more implementation for this method.

    Example

    public async afterQueryCallback(event: EventObject): Promise<void> {
        let queryInstance1 = event.getObject();
        let resultSet1 = queryInstance.getResults(); // returns array of JSON object

     let queryInstance2 = event.query1.getQueryP("another_entity");
     await queryInstance2.executeP()
        let resultSet2 = queryInstance2.getResult(); // returns array of JSON object

        // modify the resultSet
     let newResultSet = resultSet1.map((result) => {
            return Object.assign(result, resultSet2.find(obj=>obj.prop == result.prop));
        })

        queryInstance.setResults(newResultSet);
     let res = await queryInstance.getResults() // newResultResultSet
    }

setSkipMap

  • setSkipMap(skipMap): void

  • Parameters

    NameTypeDescription
    skipMapboolean

    whether to skip loading from cache or not.

    Returns void

    Description

    setSkipMap method is used to set whether to skip loading entity data from cache or not. Usually when query is executed it will load the data from the server, and if data is already present in cache it will load from cache. This method is used to skip loading data from cache and load from server only. Use skipMap only when needed: for comparing data or checking for duplicates. It may impact performance in case of large data sets.

    See

    • getSkipMap for getting the current value of skipMap
    • skipMap for getter and setter version of this function

    Example

    // qRule is the rule callback object and does not execute the query itself.
    // executeP is called on the KloQuery returned by the transaction.
    const query = await qRule.getTransaction().getQueryP("d_order");
    query.setProperty("order_id", "ORD001");
    let result = await query.executeP();
    console.log(result[0].short_text); // cached value, when the entity is already cached.

    // In the rule callback, configure the current rule query to bypass the cache.
    qRule.setSkipMap(true);
        // The framework executes the current rule query after the callback completes.

    // To execute the query explicitly, use the KloQuery instance again:
    query.setSkipMap(true);
    result = await query.executeP();
    console.log(result[0].short_text); // latest committed value from the server.
